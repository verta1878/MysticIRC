# 6.1 Content File Roles

[◀ Prev: 6.0 Writing 3.x .RIP Files](6.0-writing-rip-files.md) · [Contents](README.md) · [Next: 6.2 Asset Delivery & Storage ▶](6.2-asset-delivery-and-storage.md)

_Reconstructed edition - every claim carries an evidence tag; see [Contents](README.md) for the legend._

The content files of the 3.x generation - what each file type is for and how commands reference it: images, three font systems, and the plain-text script containers. Roles live here; **byte-level layouts are implementer material** in the techspecs linked throughout.

_Where the 2.0 edition documented essentially [one binary format](../../2.0/ripscrip/6.1-content-file-roles.md) (the BMP/DIB icon), the 3.x client ships a whole family._

## File roles

| Extension | Role | Evidence |
| --- | --- | --- |
| `.RIP` `.FN` `.COL` … | Plain-ASCII script containers - stored RIPscrip command streams distinguished only by role; the full family is in [6.0 Writing 3.x .RIP Files](6.0-writing-rip-files.md) | corpus |
| `.BMP` | Primary bitmap format - [icons](../../glossary.md), button skins, backgrounds, wallpaper ([4.0 Icons & Bitmaps](4.0-icons-and-bitmaps.md)) | 2.00a4; WP; corpus |
| `.BMH` | Button-highlight BMP variant - the pressed/highlighted state of a same-named `.BMP` UI skin ([4.3 Buttons](4.3-buttons.md)) | corpus (ICONS/\*.BMH) |
| `.BMM` | An [icon mask](../../glossary.md): the AND-stamp companion raster for transparency - defined by the 2.x spec's extension tables; no `.BMM` files are known to have shipped, and the 3.x record adds no sighting | 2.00a4 |
| `.ICN` | Legacy 1.54 icons - read + converted only (below) | HLP |
| `.JPG` | Compressed photographic images, incl. GrayPEG ([4.1 JPEG Images](4.1-jpeg-images.md)) | WP; HLP; corpus |
| `.GIF` | Paper-only: added in the ALPHA 4 draft _(v2.A4)_, dropped over LZW licensing before shipping; no 3.x client decodes it | 2.00a4; WP |
| `.WAV` | Digitized audio, played in the background ([4.5 Audio Files](4.5-audio-files.md)) | 2.00a4; HLP |
| `.RFF` | Scalable outline fonts (Atech FastFont) - global client resource, not host-delivered | corpus (FONTS/\*.RFF) |
| `atf.cfg` | Outline-font engine catalog/cache - global client resource | corpus (FONTS/atf.cfg) |
| `.maf` | MicroANSI bitmap terminal fonts - global client resource | corpus (FONTS/RIPscrip.maf) |
| `.CHR` | Borland BGI stroked (vector) fonts - global client resource | 2.00a4; corpus |

Commands reference host-deliverable files by bare name - no path or sub-directory information is allowed. Default extensions are appended when omitted (`.BMP` for icon commands, `.RIP` for playback variables); an explicitly provided extension is used verbatim. _Evidence: 2.00a4._

## Legacy `.ICN` icons (RIPscrip 1.54)

The 1.54 icon format - Borland `getimage()` memory dumps, documented in the [v1.54 reference](../../1.54/ripscrip/6.1-content-file-roles.md) - is not a native 3.x format, but the 3.0 driver retains read support by _converting_ legacy icons to BMP on the fly: the DLL exports `RIP_ConvertIconToBmp` and carries the error strings "Can't convert RIP 1.54 Icon %s to 2.0 BMP format!" and "1.54 icon file %s has an invalid width". No `.ICN` files ship with RIPtel; hosts are expected to serve BMPs.

_Evidence: HLP (RIPSCRIP.HLP error strings; RIPTEL.EXE export table)._

## Windows BMP / DIB

_Added in RIPscrip v2.A1._

The 2.00a4 decision to adopt the Windows **Device-Independent Bitmap** stands in 3.x. The older 1.54 icon format was completely inadequate for resolution- and color-independent environments: it carried no color palette and no notion of pixel format. The DIB format accommodates monochrome (1-bit), 16-color (4-bit), 256-color (8-bit), and 24-bit uncompressed images, and stores palette information in the file so that color approximation or dithering can make the image appear correct in any color environment. Explicitly _not_ supported: RLE-compressed BMPs ("Can't show compressed bitmaps") and OS/2-style BMPs. Display options include stretching to any size, dithering, transparency, color-palette manipulation, and wallpapering.

BMPs are pervasive in the corpus (102 of the 234 files in RIPtel's `ICONS/`): backgrounds, button skins (via [RIP_LOAD_BITMAP](4.0-icons-and-bitmaps.md#rip_load_bitmap)), and UI décor. Content creators normally never touch the bytes - icons are produced in a paint program, or captured on the terminal itself via [RIP_GET_IMAGE](4.0-icons-and-bitmaps.md#rip_get_image) + [RIP_WRITE_ICON](4.0-icons-and-bitmaps.md#rip_write_icon) (or per-port via [RIP_PORT_WRITE](7.0-drawing-ports.md#rip_port_write)). Implementers decoding or generating icon files should work from the [icon formats techspec](../../2.0/techspecs/3.0-icon-formats.md), whose header/color-table/pixel-block layout is unchanged in 3.x.

_Evidence: 2.00a4; WP (§3.7.1); HLP ("Can't show compressed bitmaps"); corpus._

### `.BMH` - button-highlight variants

A `.BMH` file is a **plain Windows BMP** whose extension marks it as the _highlighted/pressed_ state of a same-named `.BMP` UI skin. RIPtel ships five pairs (BUTTON, CHECKBOX, RADIO, RADIOBUT, RADIONEW): each pair has identical dimensions, bit depth, and palette, differing only in pixel data (the `.BMH` shifted toward white/highlight tones). The client swaps the `.BMH` image in on hover/click for BMP-skinned buttons, checkboxes, and radio buttons; pairing is by filename convention - `.BMH` files are never named in any script ([4.3 Buttons](4.3-buttons.md)).

_Evidence: corpus (ICONS/\*.BMH byte comparison - see [binary triage §3](../../3.0/research/riptel-binary-formats.md))._

## JPEG (and GrayPEG)

JPEG remains the only compressed image format in shipping 3.x (GIF was dropped over LZW licensing; PNG was announced but never shipped - see the [white paper](../text/RIPScrip-3.x-technical-whitepaper.txt)). All JPEGs are 24-bit; the white paper notes support for the **GrayPEG** grayscale variants. JPEG decoding is built into the driver (`jpegShow`, `LoadJPEGBuffer`, JPEG scaling-table error strings), images can be placed anywhere at any size, and progressive ("display while downloading") rendering was advertised but noted as not working in RIPtel 3.1. Seven JPEGs ship in the demo corpus, driven by [RIP_IMAGE](4.1-jpeg-images.md#rip_image) and the `$(file.JPG$` [playback prefix](5.3-local-playback.md). Byte-level decoder notes are in the [JPEG techspec](../../2.0/techspecs/3.1-jpeg-images.md).

_Evidence: WP (§3.7.2, GrayPEG); HLP (jpeg_ strings; readme progressive-display note); corpus (N2*PHOTO.RIP, SPECLEFX.RIP).*

## `.WAV` audio

A digitized audio file, played in the background by [RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio) or the `$)FILE.WAV$` playback prefix ([5.3](5.3-local-playback.md)), and stoppable with `$OFF$`. The 3.0 driver plainly supports audio (audio configuration, `AUDIO=TRUE` in RIPscrip.ini, the DLL export `RIP_AudioSupport`), but the demo corpus ships no audio files and never issues the command. Terminals that store audio in a translated local format must still answer [file queries](6.2-asset-delivery-and-storage.md) as if the WAVE original were on disk. Format details: [audio techspec](../../2.0/techspecs/3.4-audio.md).

_Evidence: 2.00a4; HLP - not observed in the RIPtel demo corpus._

## Fonts are not content files

Fonts are **global client resources, never host-delivered per connection** - they resolve only from the client's font store (`FONTS\`), outside the [connection directory](../../glossary.md) model of [6.2](6.2-asset-delivery-and-storage.md). The 3.x client ships three font systems plus a catalog file; creators select them by name/number through the font commands ([3.0 Text Output & Fonts](3.0-text-output-and-fonts.md)):

- **`.RFF` outline fonts (Atech FastFont)** - the scalable outline-font system is a licensed third-party engine, Atech Software's "FastFont"; `.RFF` is evidently "RIPscrip FastFont", renamed from Atech's `.FF1`. Eight shipped faces (BRUSH, COBB, DEFAULT, DIXON, EUREKA, MARIN, OAKLAND, SYMBOL), 224 glyphs each (0x20-0xFF) on a 1000-units-per-em square, with **ten style variants per file** - base, `Th`in, `Cn` condensed, `Wd` wide, `Ex` expanded, plus hollow versions of all five - exactly the family-suffix names the corpus passes in extended-font-style commands ("Marin", "Cobb Th", …). RIPterm 2.30 (October 1997) shipped five of the families as byte-identical `.RFF` files - both generations are preserved in the [RIPterm 2.30 font assets](../../2.0/assets/fonts/README.md). _Evidence: corpus (FONTS/\*.RFF - [binary triage §1](../../3.0/research/riptel-binary-formats.md)); WP (§3.4.1)._
- **`atf.cfg`** - the FastFont engine's binary **catalog/cache**: a pre-scanned registry mapping style names to files so the rasterizer needn't open every font at startup. Machine-generated and safe to rebuild. _Evidence: corpus (FONTS/atf.cfg)._
- **`.maf` MicroANSI bitmap fonts** - `FONTS/RIPscrip.maf` holds the fixed-cell fonts used for ANSI/text-window emulation: six resolution records, each with five font-size subrecords of raw glyph bitmaps for the full 256-character (CP437) set - the per-resolution renderings behind the terminal text modes and the `$TWFONT$` "MicroANSI" font numbers ([1.4 Terminal & ANSI View](1.4-terminal-ansi-view.md)). _Evidence: corpus (FONTS/RIPscrip.maf); HLP (MicroANSI font-loading error strings; MESSAGES.HLP text-mode list)._
- **`.CHR` Borland BGI stroked fonts** - the classic 1.54 vector "system font" set survives untouched: ten standard Borland BGI stroked-font files (BOLD, EURO, GOTH, LCOM, LITT, SANS, SCRI, SIMP, TRIP, TSCR). The format is Borland's, publicly documented, and unchanged; nothing RIPscrip-specific was added. _Evidence: 2.00a4 (system-font lineage); corpus (FONTS/\*.CHR); HLP ("BGI font" error strings)._

> _Editor's note:_ the FastFont format has full byte-level documentation under the earliest-version rule - the header, style-record, glyph-section, kerning, and `ATF.CFG` layouts live in the [v2.0 FastFont techspec](../../2.0/techspecs/3.2-fastfont-fonts.md), with the RIPtel-specific delta (the BRUSH/EUREKA/OAKLAND families and the regenerated `atf.cfg`) in the [v3.0 techspec](../techspecs/3.2-fastfont-additions.md). MicroANSI likewise: [v2.0 base](../../2.0/techspecs/3.3-microansi-fonts.md), [v3.0 `.maf` delta](../techspecs/3.3-microansi-maf-delta.md); the 1.54 stroked/bitmap lineage is in the [v1.54 techspecs](../../1.54/techspecs/3.1-bgi-stroked-fonts.md). Those pages supersede the research triage for format details.

> _Editor's note:_ the RIPtel install also contains client-internal binary files - resource containers and the variable database behind the [persistent variable store](../../glossary.md). These are implementation artifacts of one client, **not host-deliverable content and not specification surface**; they are decoded as research context in [`riptel-resource-containers.md`](../../3.0/research/riptel-resource-containers.md).
