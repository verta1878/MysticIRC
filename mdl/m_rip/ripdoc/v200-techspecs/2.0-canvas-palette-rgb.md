# Canvas Tiers, Palette & RGB Rendering

[◀ Prev: 2.x Stream Conventions](1.0-stream-conventions-delta.md) · [Contents](README.md) · [Next: Fill Defects ▶](2.1-fill-defects.md)

RIPscrip 2.x breaks the 1.54 ceiling of 16 colors from a 64-color master palette: a 256-entry drawing palette plus an optional direct-RGB color mode with arbitrary bit precision. What the spec leaves open: the logical canvas/resolution tiers and color depths the shipping client actually rendered to, and how palette and RGB values resolve to pixels on them.

_The language side is fully specified in [Color, Audio & Text Windows](../ripscrip/2.0-color-modes-and-palettes.md) and is not restated here._

## Language surface (spec links)

- **Drawing palette** - the 256-entry color lookup table ([The Drawing Palette](../ripscrip/2.0-color-modes-and-palettes.md#the-drawing-palette)); entries 0-15 remain the legacy 16-color "desktop palette" still adjustable by the 1.54 [RIP_SET_PALETTE](../ripscrip/2.0-color-modes-and-palettes.md#rip_set_palette)/[RIP_ONE_PALETTE](../ripscrip/2.0-color-modes-and-palettes.md#rip_one_palette); the full table is addressed by [RIP_ONE_DRAWING_PALETTE](../ripscrip/2.0-color-modes-and-palettes.md#rip_one_drawing_palette) and [RIP_SET_DRAWING_PALETTE](../ripscrip/2.0-color-modes-and-palettes.md#rip_set_drawing_palette), whose RGB parameters are four-digit base-64 [UltraNums](../../glossary.md#protocol--syntax) regardless of the base-math setting.
- **Direct-RGB mode** - [RIP_SET_COLOR_MODE](../ripscrip/2.0-color-modes-and-palettes.md#rip_set_color_mode) and the [`$COLORMODE$`](../ripscrip/5.1-text-variables.md#colormode) environment variable; resolution semantics in [Palette Mapping and Direct RGB Mode](../ripscrip/2.0-color-modes-and-palettes.md#palette-mapping-and-direct-rgb-mode), component bit-scaling rules included.
- **Default palette** - on any reset the 256 entries load the fixed table (16 ANSI colors, 16-step gray ramp, 224-entry RGB cube indexed `INDEX = 32 + BLUE + GREEN*4 + RED*32`) transcribed in full in [Default RGB Values of Color Lookup Table](../ripscrip/2.0-color-modes-and-palettes.md#default-rgb-values-of-color-lookup-table).

One shipped-client corroboration worth recording: the same 16-color, gray-ramp, and RGB-cube DAC blocks appear **verbatim** (6-bit VGA DAC triplets) inside the client's resource container - observed in the RIPtel-era client resource file ([research notes](../../3.0/research/riptel-resource-containers.md#ripscripres---client-resource-container)) - so the shipping engine's default palette is byte-for-byte the specified table, not an approximation.

## Resolution tiers as shipped

RIPscrip itself never selects a video mode - the client owns the display, and the world-coordinate system ([RIP_SET_WORLD_FRAME](../ripscrip/1.3-world-view-virtual-canvas.md#rip_set_world_frame)) exists precisely so scenes are resolution-independent. What matters to an implementation is the set of logical canvases the definitive client rendered to:

| Canvas | Color depths | Notes |
| --- | --- | --- |
| 640×350 | 16 | the EGA floor: guaranteed-safe **default**; ties to the [MicroANSI](3.3-microansi-fonts.md) "640x350 EGA" font record |
| 640×480 | 16 / 256 |  |
| 800×600 | 16 / 256 |  |
| 1024×768 | 16 / 256 | the ceiling actually exposed |

- **Ceiling: 1024×768 at 256 colors.** The 2.0 and 2.30 manuals contain no 15/16/24-bit mode anywhere - no "32,768", "65,536", or "16 million color" text exists in either manual - and every entry in the readable 2.0 video-mode database is 16 or 256 colors at ≤ 1024×768 (RIPTERM.DOC mode dialog; `RIPTERM.VID`). Direct-RGB mode therefore **always** resolved to closest-match palette colors on the shipping DOS clients; no shipped configuration rendered true RGB.
- **1280×1024 was prepared but never exposed:** the [MicroANSI container](3.3-microansi-fonts.md#resolution-directory-60-byte-records) carries a complete 1280×1024 terminal-font set, the [widget images](3.5-ui-resources.md#img-widget-images---format-decoded) include a 1280×1024 tier, and the 2.30 `RIPTERM.EXE` contains mode-identifier strings up to `VESA1280x1024X`/`Y`/`YY` - but no shipped video-mode database entry reaches past 1024×768 and no manual mentions the resolution as selectable. _(Whether some undocumented path could activate it is unverified.)_
- Driver plumbing (immaterial to reimplementation, noted for provenance): the mode list was data-driven from a per-video-card database, `RIPTERM.VID` - plain text in 2.0 (`TOTAL=117` entries like `DEV=0x1A22 DESC="VESA Super VGA" HRES=800 VRES=600 COLORS=256 STATUS=-1`), a binary compile in 2.30 covering "over 237 different kinds of video cards" (2.30 RIPTERM.DOC) - with generic VESA Super VGA and 8514/A fallbacks. None of this affects the tier table above.

### Implementation notes for emulators

- A faithful "2.x terminal" is a palettized 256-color surface at one of the four shipped canvas sizes, defaulting to 640×350×16 EGA; 16-color modes use the desktop-palette semantics, 256-color modes the full drawing palette with the default table.
- Direct-RGB commands must still render in palettized environments via closest-match against the active palette (spec, [Palette Mapping and Direct RGB Mode](../ripscrip/2.0-color-modes-and-palettes.md#palette-mapping-and-direct-rgb-mode)); the default 224-entry cube is designed so the match is a constant-time index computation (`INDEX = 32 + BLUE + GREEN*4 + RED*32`) rather than a search.
- The 16↔256-color duality is why the default palette's first 16 entries exactly match the ANSI text palette: text windows and graphics share one palette, and [CP437 text](3.3-microansi-fonts.md) renders with the same 16 base colors in either depth.
- Color 0 is the screen background everywhere; changing it repaints the whole screen (spec).
- Canvas-size and aspect-ratio policy for modern renderers lives in [version/implementation.md](../../implementation.md), not here.
