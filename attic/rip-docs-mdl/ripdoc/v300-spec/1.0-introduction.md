The RIPscrip 3.x generation - the completed, shipping form of the 2.0 redesign: its inherited design goals, the 3.0 identity evidence, the revision history and its differences from 1.54 and from the last published specification draft, the state of modern implementations, and the evidence model this reference rests on.

## What RIPscrip 3.x Is

_Evidence: WP; 2.00a4._

RIPscrip ("Remote Imaging Protocol script") is TeleGrafix Communications' text-based graphical scripting language for online services. It encodes vector graphics, bitmapped images, mouse-driven user interfaces, fonts, audio, and terminal text into a stream of 7-bit printable ASCII that can be transmitted over any connection capable of carrying text, and intermixed freely with ordinary TTY and ANSI/VT-102 output. The language is object-oriented rather than raster-oriented: a scene is a sequence of compact drawing commands, not a bitmap.

RIPscrip 3.x is the third generation of the language - the completed form of the 2.0 design that TeleGrafix circulated as the ALPHA specification drafts of 1993-1994, shipped in RIPterm 2.0 and RIPtel 3.1, and described publicly in the December 1996 [RIPscrip 3.0 Technical White Paper](../text/RIPScrip-3.x-technical-whitepaper.txt). It adds to the 1.54 baseline: [drawing ports](../../glossary.md) and offscreen bitmaps, [world coordinates](../../glossary.md) and resolution independence, 256-color and direct-RGB color, data tables with protection, a save/restore backup system, outline fonts, JPEG images, WAV audio, a flowed-text column system, and a greatly expanded text-variable/host-command language.

## Design Goals Inherited from the Original Language

_Evidence: 2.00a4._

The founding rationale of the language, in TeleGrafix's own words from the 2.00 specification, applies unchanged to 3.x. As system operators of many bulletin board systems, they had wished for some form of Graphical User Interface for their boards, found every existing solution inadequate in one way or another - incomplete, difficult to implement, too complex, or lacking in graphics development tools - and so decided to write their own graphical script language.

RIPscrip is a text based script language for displaying online graphics. The script language conforms to 7-bit ASCII, avoiding the use of Extended ASCII characters. This allows transmission over X.25 networks and other carriers that do not support full 8-bit binary transfers easily. RIPscrip allows RIPscrip graphical statements to be mixed with printable ASCII text and [de facto standard] ANSI/VT-100 directives. RIPscrip can dynamically determine what is graphics and what is text and display them appropriately in separate windows (a graphics window and a [text window](../../glossary.md)). And if you must have your own proprietary commands, RIPscrip has room for that too.

The language's efficiency stems from its compactness and developmental planning. It is entirely Object Oriented instead of Raster Oriented for efficient transmission of data and powerful editing capabilities. Earlier graphical script languages (Avatar and Skypix among others) used special command characters; traditional script languages use English words ("BOX 0,0 100,50") - incredibly bulky when pictures are comprised of hundreds or thousands of individual graphical operations. The main strategy was therefore to make the language as efficient as possible without going completely binary, allowing immediate installation onto any ASCII text-based host system. The unreadability of the language was justified by the limited bandwidth of the era's modems - the language must be compact.

The RIPscrip language is made publicly available and is freely licensed by TeleGrafix Communications, Inc. - the language can be used in the creation of other products, but it is not public domain; TeleGrafix maintains the copyright. RIPscrip, RIPaint, RIPdraw, and RIPterm are trademarks of TeleGrafix Communications, Inc., and products that use RIPscrip were required to state so with the trademark statement. _(v2.A3)_

## Evidence Basis for This Edition

Unlike the [1.54](../../1.54/ripscrip/README.md) and [2.0](../../2.0/ripscrip/README.md) references, this edition is **not** a conversion of an official document. TeleGrafix's own product list advertised a "RIPscrip 3.0 protocol specification," and the white paper promises a "RIPscrip 3.0 Language Reference," but no such document has ever been located. This edition therefore reconstructs the 3.x language from five converging sources:

1. **The RIPscrip 2.00 ALPHA 4 specification** (December 1994) - the last published TeleGrafix language reference, and the documented baseline that 3.x completes. Where 3.x evidence shows a behavior unchanged from 2.00a4, this edition adapts the [2.0 reference's](../../2.0/ripscrip/README.md) text.
2. **The RIPscrip 3.0 Technical White Paper** (December 1996) - architecture and feature prose, [preserved in full](../text/RIPScrip-3.x-technical-whitepaper.txt) as the verbatim source document.
3. **RIPSCRIP.HLP recovered strings** - the complete error-message and command-name string table of the RIPSCRIP.DLL 3.0.7 parser, extracted from the RIPtel 3.1 install. It fixes the 3.0 command inventory (~90 `RIP_*` names) and many hard limits. See the [help extraction report](../../3.0/research/riptel-help-extraction.md).
4. **The 116-script RIPtel demo corpus** - TeleGrafix's own demo scenes (22,921 parsed commands, self-documented with 305 prose comments), the primary source for on-the-wire opcodes and syntax. See the [script census](../../3.0/research/riptel-script-census.md).
5. **SyncTERM's implementation** - `ripper.c` in the Synchronet source tree, the only open-source implementation that answers the version query as RIP 3.0. Cited by line number throughout.

Every section in this edition carries an _Evidence:_ line naming which of these sources supports it (`2.00a4`, `WP`, `HLP`, `corpus`, `SyncTERM`); editorial inferences are marked _(hypothesis)_. The full legend is in the [Contents](README.md). Material inherited from the published 2.x specification additionally keeps the spec's own revision markers - `_Added in RIPscrip v2.A1._` lines and `_(v2.A3)_` margin notes - exactly as the 2.0 reference preserves them, so a reader can always tell which ALPHA draft introduced a given behavior.

## The 3.0 Identity

_Evidence: HLP; corpus; SyncTERM (ripper.c:7619)._

"RIPscrip 3.0" is a renaming, not a redesign. The evidence from RIPtel 3.1 (October 1997) is unambiguous:

- RIPtel 3.1 ships **driver version 3.0.7** of RIPSCRIP.DLL, per its readme.
- The engine's internal file headers self-identify as **"RIPterm v2.0"** - the resource file, the MicroANSI font file, and the help resources all carry `RIPterm v2.0` signatures.
- The RIPTEL.HLP FAQ gives the auto-detect reply as **`RIPSCRIP03000`** (see [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md) for the handshake; SyncTERM answers with the 14-byte `RIPSCRIP030001`).

In other words, RIPscrip 3.0 **is** the completed RIPscrip 2.x engine: the 2.00 ALPHA feature set, finished, debugged, and shipped under a new major version number. This is why the 2.00a4 specification remains the structural backbone of this edition.

## Revision History

_Evidence: 2.00a4; WP; HLP._

| Revision | Date | Notes |
| --- | --- | --- |
| 1.54 | 1993 | Last published 1.x specification; the universal interoperability baseline. See the [v1.54 reference](../../1.54/ripscrip/README.md). |
| 2.00 A0-A4 | 1993-Dec 1994 | The five ALPHA drafts of the 2.0 specification, introducing ports, tables, world coordinates, UltraNums, and the rest of the modern architecture. Per-revision change logs are preserved in the [2.0 Introduction](../../2.0/ripscrip/1.0-introduction.md). |
| 2.0 / 2.1 / 2.2 | 1995-1997 | The undocumented "RIPscrip-2" product era: the engine as shipped in RIPterm Professional 2.0 (Jan 1995), 2.20.00 (Nov 19, 1995), 2.20.01 (Nov 28, 1995), and 2.30 (Oct 27, 1997), with **no specification published after ALPHA 4** (no product labeled "2.1" has surfaced). The shipping engine moved past the draft from day one - RIPterm Pro 2.0 already used the 26-character RIP_EXTENDED_FONT_STYLE argument block (SHADOW.RIP) rather than ALPHA 4's 13-character form, and v2.20.01 added the icon-transparency flag (`<flags2>` bit 128) to RIP_BUTTON_STYLE, absent from the ALPHA 4 table. Features often credited to "3.x" were already shipping in the January 1995 2.0 release - background **.WAV audio playback** (specified since ALPHA 3; HMI sound drivers), JPEG image display, SVGA/256-color modes, BMP icons, and Atech `.FF1` outline fonts (see the [RIPterm 2.30 font assets](../../2.0/assets/fonts/README.md)). See [4.5 Audio Files](4.5-audio-files.md). |
| 3.0 | 1995-1996 | The 2.x design finalized and renamed. Publicly described by the Dec 1996 white paper; no language reference published. |
| 3.0.7 | Oct 1997 | Driver shipped with RIPtel 3.1 "Visual Telnet" - the concrete engine this edition documents. |

One notable change between the 2.00a4 draft and the shipping 3.0: **GIF support was dropped.** The 2.A4 draft added GIF alongside JPEG for compressed images, but the white paper explains it had to be removed "due to outrageous licensing conditions for the compression algorithm LZW," leaving JPEG as the sole compressed image format (with PNG named as the intended successor). See [the white paper on image formats](../text/RIPScrip-3.x-technical-whitepaper.txt).

### The 2.0 ALPHA Drafts and the Shipping Engine

_Evidence: 2.00a4._

The 2.00 ALPHA 4 draft ("RIPscrip Graphics Protocol Language, Technical Reference" - Version 2.00, Revision ALPHA 4, December 13th 1994) is the last published specification of any kind, and its ALPHA lineage matters for reading this reference: the drafts were an ongoing culmination revised as A0 through A4, each sub-revision flagged in the document's margin (`_(v2.A3)_`-style markers, preserved throughout this reference on inherited material). The A0 draft defined the resolution-independent coordinate system, 24-bit color encoding, the 36-slot text-window/viewport/style tables, and base-math variation; A1 added the header command, save/restore protection, extended fonts, and UU-encoded data blocks; A2 added command grouping and borderless fills; A3 added drawing ports, WAV audio, and file deletion; A4 reworked text variables, data tables, and the extended text window. The complete per-revision change logs - creator-relevant history for understanding why commands look the way they do - are carried in full in the [2.0 Introduction](../../2.0/ripscrip/1.0-introduction.md). The shipping 2.30-generation clients already diverged from the draft in documented places (auto-sense reply, the Base Math opcode, the extended-font layout - see the [2.0 reference's spec-status note](../../2.0/ripscrip/1.0-introduction.md)); the 3.0 engine this edition documents inherits those shipping resolutions, not the draft positions.

## Differences from 2.00 ALPHA 4

_Evidence: corpus; HLP; WP._

Relative to the last published specification draft, the shipping 3.0 engine differs as listed below. Note that these differences accumulated **across the 2.0-2.2 product releases as well as the 3.0 renaming** - with no specifications published after ALPHA 4, the exact release where each feature landed is mostly unrecorded; where evidence exists (e.g. WAV audio and the reworked extended-font-style block shipping in RIPterm Pro 2.0), the relevant section says so.

- **Adds new drawing primitives** never documented in any spec: skewed ovals (`&`, `-`, `]`, `[`, `+`), the filled oval chord (`_`), markers (`;`), poly-polygons with even-odd fill (`<`), and bounded text (`"`). All are named or demonstrated in TeleGrafix's own NEWCMDS.RIP and companion demos - see [the script census](../../3.0/research/riptel-script-census.md) and the [2.2 Curves](2.2-curves.md) and [2.3 Shapes & Fills](2.3-shapes-and-fills.md) pages.
- **Resolves the 2.00a4 opcode collision**: RIP_SET_BASE_MATH is level-0 `J` on the wire, leaving `b` to RIP_EXTENDED_TEXT_WINDOW. See [1.2 Math & Coordinates](1.2-math-and-coordinates.md).
- **Adds the flowed-text column system** - `1e` column regions, linked multi-column layouts, overflow paging, and RIP_SelectArticle - the "powerful column system" advertised for newspaper-style presentation. See [3.1 Column Text System](3.1-column-text-system.md).
- **Adds a conditional/macro layer**: `<<IF …>> <<ELSE>> <<ENDIF>>` inline conditionals, `<<NAME>>` macro expansion, the `$&VAR$` dereference form, and `ID=n:` mouse-field identities. See [5.2 Templates & Conditionals](5.2-templates-and-conditionals.md).
- **Adds web integration**: `$GOTOURL(var)$` launches a URL held in a text variable - 1997-era web/BBS convergence.
- **Formalizes scene header segments** - a per-scene header mechanism carrying data-table flags and entries, coordinate size, direct-RGB bit count, general flags, and a revision code. See [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md#scene-header-segments).

## Differences from 1.54

_Evidence: 2.00a4; HLP; corpus._

Everything the 2.00 ALPHAs introduced applies: ports, tables, backup areas, world coordinates, 256/direct-RGB color, base-math variation, and the expanded command levels - the fundamentals chapters of this edition cover each. For interoperating with 1.54-era content, 3.x provides the **`$COMPAT$`** text variable, which sets the environment to RIPscrip 1.54 settings - the classic 640×350 EGA coordinate space and defaults. TeleGrafix's own demo scenes issue `$COMPAT$` before playing 1.54-style artwork (21 uses in the corpus), making it the standard bridge between the two coordinate worlds. The driver also retains 1.54 `.ICN` icon handling, converting old icons to BMP on the fly ("Can't convert RIP 1.54 Icon %s to 2.0 BMP format!").

Two backward-compatibility subtleties inherited from the 2.0 redesign are worth restating for authors converting 1.54 material: XOR (and the other raster write modes) now apply to **all** primitives including curves and filled areas, where 1.54 limited XOR to simple line primitives _(v2.A1)_; and the resolution-independent fill model means filled rectangles inset one pixel from their right and bottom coordinate lines, which can open one-pixel gaps in 1.54 artwork replayed under a non-1.54 environment - see [1.2 Math & Coordinates](1.2-math-and-coordinates.md#the-mathematics-of-graphics-and-coordinates) for the full rules _(v2.A1)_. Filled objects' borders, always drawn in 1.54, can be turned off from 2.0 onward (they default on for compatibility) _(v2.A3)_. _Evidence: 2.00a4._

## Implementation Status

_Evidence: SyncTERM; editorial survey._

No modern implementation covers RIPscrip 3.x in full:

| Implementation | Coverage |
| --- | --- |
| SyncTERM | 1.54 plus a substantial subset of 2.0/3.x additions; the only implementation answering the version query as 3.0 (`RIPSCRIP030001`). Its RIPv3 mode is "idealized, not bug-compatible" with 1.54. |
| icy_tools, fTelnet, PabloDraw | RIPscrip 1.54 only (varying subsets). |
| Qodem | Detects and discards RIP sequences. |

The practical takeaway: **1.54 is the interoperable floor**, SyncTERM is the only living implementation of anything beyond it, and the original RIPSCRIP.DLL 3.0.7 driver (via RIPtel under emulation) remains the reference behavior for the full language. See [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md#ansi-sequences-auto-sensing) for version identification details.
