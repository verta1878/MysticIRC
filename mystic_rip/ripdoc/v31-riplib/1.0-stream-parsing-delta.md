# 1.0 Stream Parsing Delta

[Contents](README.md) · [Next: 2.0 Fill Patterns & FPU Rendering ▶](2.0-fill-patterns-and-rendering.md)

_Delta against [`.RIP` Stream & File Parsing](../../1.54/techspecs/1.0-rip-stream-parsing.md) in the 1.54 techspecs. See the [tree README](../README.md) for standing and provenance._

One parser change carries a v3.1 label in RIPlib's wire-format segment. It is not in the §A2G.1-7 list, and it changes no command syntax - it changes when the parser is willing to _start_ a command.

> RIPlib's **text-escape set** also carries v3.1-era annotations, but the differences there are baseline rather than extension - see [3.0-riplib → 1.0 Stream Parsing & Escapes](../../3.0-riplib/techspecs/1.0-stream-parsing-and-escapes.md#the-escape-set-and-its-attribution).

## The relaxed `!` trigger

RIPscrip recognizes `!` as a command introducer only at a line boundary. RIPlib's baseline states this as four cases - first byte of the stream, or immediately after CR (`0x0D`), LF (`0x0A`) or FF (`0x0C`) - and passes a mid-line `!` through to the text renderer as a literal exclamation mark. `spec (01 §1.8)` That matches the specification's rule ([1.54 line structure](../../1.54/techspecs/1.0-rip-stream-parsing.md#line-structure)).

**v3.1 additionally accepts `!` immediately after an ANSI CSI sequence terminator.** `spec (01 §1.8)` The motivating case is a host that clears the screen and starts a scene on one line:

```text
ESC[2J!|*|          clear screen + RIP reset, same line
```

Without the relaxation the `!` is literal text and the scene never starts.

### This problem already has a documented solution

⚠ **Divergence in approach, not in syntax.** The specification's answer to "the host needs to introduce a command mid-line" is syntax rule 12's alternate introducers: `!` may be replaced by **SOH (`0x01`)** or **STX (`0x02`)**, and those two _are_ accepted anywhere in a line - deliberately a host-only capability, since BBS users could not readily type control characters. A host emitting `ESC[2J\x01|*|` gets the intended behavior from any conforming terminal, including 1.54-era ones, and the shipped 2.x corpus already opens with exactly that form. RIPlib's baseline does not implement rule 12; that gap is recorded in [3.0-riplib → alternate command introducers](../../3.0-riplib/techspecs/1.0-stream-parsing-and-escapes.md#alternate-command-introducers).

The two mechanisms coexist without conflict - RIPlib's relaxation only widens where `!` is honored - but content relying on it will not start on a terminal that implements the documented rule, whereas SOH/STX works everywhere. Prefer the introducer for portability; implementing rule 12 upstream would make this extension unnecessary.

The relaxation also has a cost the introducer does not: a line of ordinary text that happens to contain an ANSI sequence followed by `!` (an exclamation mark opening a sentence right after a color change, say) is parsed as a command on a `RIPSCRIP031001` terminal. The specification's line-boundary rule exists precisely to make that impossible.

## Backslash line continuation

Unchanged. The odd/even trailing-backslash continuation rule ([1.54](../../1.54/techspecs/1.0-rip-stream-parsing.md#the-80-column-convention-and--continuation)) carries into v3.1 with no annotation in RIPlib's segments.
