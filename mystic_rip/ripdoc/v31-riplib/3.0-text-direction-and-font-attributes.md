# 3.0 Text Direction & Font Attributes (§A2G.2, §A2G.3, §A2G.7)

[◀ Prev: 2.0 Write Modes](2.0-write-modes.md) · [Contents](README.md) · [Next: 7.0 Port Flags ▶](7.0-port-flags.md)

_Covers RIPlib §A2G.2, §A2G.3 and §A2G.7. Delta against [RIP_FONT_STYLE](../../3.0/ripscrip/3.0-text-output-and-fonts.md#rip_font_style) and [RIP_EXTENDED_FONT_STYLE](../../3.0/ripscrip/3.0-text-output-and-fonts.md#rip_extended_font_style) in the 3.0 reference; see the [tree README](../README.md) for standing and provenance._

Two changes to how stroke-font text is drawn: the `direction` field of `|Y` gains a third value and its second value is redefined (§A2G.2, §A2G.7), and font attribute bits are given actual rendering behavior (§A2G.3).

## Text direction - a third value, and a redefined second

RIPscrip inherits its vertical text convention from the Borland BGI, where `VERT_DIR` places the first character at the origin and advances **upward**. Read top-to-bottom on screen, `HELLO` therefore appears as `OLLEH`. RIPlib observes that no known BBS ever sent vertical text, and redefines the value rather than preserving the behavior. `A2G.2`

| `direction` | This repository (1.54 · 2.00a4 · 3.0) | RIPlib v3.1 |
| --- | --- | --- |
| `00` | Horizontal, left to right | Horizontal, left to right |
| `01` | Vertical, baseline to the right, read **bottom to top** | ⚠ Vertical, **top to bottom**, glyphs rotated CW |
| `02` | _(undefined)_ | Vertical, **top to bottom**, glyphs rotated CCW - **new** |

⚠ **Divergence** on `01`. The 1.54 specification states the vertical case explicitly - _"Vertical text is drawn with the base-line to the right, and is read from bottom to the top"_ - and the 3.0 reference carries the same reading. RIPlib's `01` renders the opposite way up. The practical risk is small (the corpus contains no vertical `|Y` text, which is what motivated the change) but the two are not interchangeable, and content authored against either reads upside-down on the other.

Both RIPlib vertical directions advance the cursor **downward** (`Y += width`); the rotation only determines which way a reader tilts their head. `A2G.2`

- `01` (CW) is readable tilting the head **right** - the US/UK book-spine convention.
- `02` (CCW) is readable tilting the head **left** - the French book-spine convention.

Glyph coordinate transforms, from stroke deltas to screen: `A2G.2`

```text
Direction 0 (horizontal):   screen_x = origin_x + stroke_dx
                            screen_y = origin_y - stroke_dy    (BGI Y inverted)

Direction 1 (CW):           screen_x = origin_x + stroke_dy
                            screen_y = origin_y + stroke_dx

Direction 2 (CCW):          screen_x = origin_x - stroke_dy
                            screen_y = origin_y - stroke_dx
```

**Validation.** `direction` is a 2-digit MegaNum (range 0-1295); RIPlib accepts `0`-`2` and **rejects the command outright** for anything higher, leaving state unchanged. Values `3`-`35` are reserved, with arbitrary-angle rotation named as the likely future use. `A2G.7`

> The 3.x record already goes further in a different direction: the shipped `RIP_EXTENDED_FONT_STYLE` (`|y`) carries **string rotation × character rotation** as a pair of fields, and the FONTS.RIP demo exercises all sixteen combinations - see the [3.0 entry](../../3.0/ripscrip/3.0-text-output-and-fonts.md#rip_extended_font_style). RIPlib's three-value `|Y` field is the narrower, stroke-font-only mechanism.

Wire format is unchanged: `!|Y<font:2><direction:2><size:2><res:2>` - e.g. `!|Y010200` for Triplex, direction 2 (CCW), size 1. `A2G.2`

## Font attributes given rendering behavior

RIPlib defines a `RIP_FONT_ATTRIB` command carrying four attribute bits, describes them as parsed-but-never-applied through v3.0, and implements all four for BGI stroke fonts in v3.1. `A2G.3` `spec (04 §4.18)`

| Bit | Value | Attribute | RIPlib rendering |
| --- | --- | --- | --- |
| 0 | `0x01` | Bold | Each stroke segment drawn twice, the second offset 1px right - thickens without changing metrics |
| 1 | `0x02` | Italic | Per-point X shear proportional to Y, `shear = font.top * scale / 5`, computed in floating point |
| 2 | `0x04` | Underline | Horizontal rule at baseline + 2px spanning the string width; for vertical text, a vertical bar 2px left of the origin |
| 3 | `0x08` | Shadow | String drawn twice - first dimmed and offset (1, 1), then normally. Shadow color halves each RGB332 channel: `(color >> 1) & 0x6D` |

Attributes are **cumulative** (`bold + italic + underline` is valid) and apply **only to BGI stroke fonts**, font IDs 1-10; the bitmap font (ID 0) ignores them. `A2G.3`

Wire format: `!|f<attrib:2><reserved:2>` - `!|f0300` for bold + italic, `!|f0700` for bold + italic + underline. `spec (04 §4.18)`

### Two divergences worth flagging

⚠ **The command letter collides**, and the collision is a baseline disagreement rather than something §A2G.3 introduces - it is documented in [3.0-riplib → 9.0 Command Inventory Comparison](../../3.0-riplib/ripscrip/9.0-command-inventory-comparison.md#prologue-critical---j-and-f). In short: this repository's record assigns Level-0 `f` to [RIP_SET_WORLD_FRAME](../../3.0/ripscrip/1.3-world-view-virtual-canvas.md), and 90 of the 116 corpus scenes open with `!|J10|n2000|M08|fZKQO`, so a `RIPSCRIP031001` terminal reads a live prologue field as a font-attribute command. §A2G.3 is the feature that rides on that assignment, so resolving the letter is a precondition for it.

⚠ **The bit assignment differs from the documented style flags.** `RIP_EXTENDED_FONT_STYLE`'s `<style>` field - the canonical place facings live - defines `01` bold, `02` italic, `04` **strike-out**, `08` **underline** ([3.0 entry](../../3.0/ripscrip/3.0-text-output-and-fonts.md#rip_extended_font_style)). RIPlib's attribute byte agrees on bold and italic, then assigns `04` to underline and `08` to shadow, with no strike-out. Shadow is not absent from the 3.x record either - the TELLISTS.MNU corpus comments narrate _"Marin, centered, bold w/ dropshadow"_ - it simply lives in the extended-font mechanism rather than a separate attribute byte.
