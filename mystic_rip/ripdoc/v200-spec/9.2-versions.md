# 9.2 Version Identification Reference

[◀ Prev: 9.1 Text Variable Reference](9.1-text-variable-reference.md) · [Contents](README.md) · [Next: 9.3 Host Command & Control Character Reference ▶](9.3-host-command-reference.md)

Every known RIPscrip version identification string of the 2.x generation, with provenance. The identification phrase is the reply to the [`ESC[!` auto-sense query](1.1-protocol-and-command-hierarchy.md#ansi-sequences-auto-sensing) and the value of [`$RIPVER$`](5.1-text-variables.md#ripver). The phrase format (`RIPSCRIPxxyyvs`: major `xx`, minor `yy`, vendor `v`, sub-version `s`) is unchanged from 1.54 - see the [v1.54 versions reference](../../1.54/ripscrip/9.2-versions.md) for the field breakdown and the 1.5x strings.

## Known 2.x-generation identification strings

**Only one 2.x-generation identification string was ever observed: `RIPSCRIP020000`** - version 02.00 with the vendor and sub-version digits zeroed. Every shipping engine of the line carries the identical literal, byte-verified by `strings` over the executables (2026-08-08):

| String | Reading | Provenance |
| --- | --- | --- |
| `RIPSCRIP020000` | v2.00, generic vendor 0, sub-version 0 | `RIPTERM.EXE` of RIPterm Professional 2.0 (`~/src/rip-tools/RIPTerm2.0/extracted/`) |
| `RIPSCRIP020000` | identical | `RIPTERM.EXE` of the 2.2x build (local reference copy `~/src/rip-tools/RIPTerm2.22/`) |
| `RIPSCRIP020000` | identical | `RIPTERM.EXE` of RIPterm 2.30 (`~/src/rip-tools/artifacts/ripterm-2.30/extracted/`) |

The reported language level never advanced past 02.00 through the end of the RIPterm line (October 1997), even as the product versions moved 2.0 → 2.20 → 2.30 - the jump to `RIPSCRIP03000…` arrives only with the RIPtel-era 3.0 driver (see the [v3.0 versions reference](../../3.0/ripscrip/9.2-versions.md)).

## Vendor codes in the 2.x specification

The 2.00 ALPHA 4 draft extends the 1.54 vendor table - `0` generic, `1` RIPterm, `2` QmodemPro, adding `3` = deltaComm (Telix) and `4` = QmodemPro for Windows - while simultaneously declaring vendor determination via the response **obsolete** in favor of the `$TERMINFO()$`, `$IFS()$`, and `$LANGUAGE$` text variables; `ESC[!` remains the way to detect RIP capability itself. _(v2.A4)_ No third-party terminal's 2.x-level identification string (Telix, QmodemPro) has been recovered, and no evidence shows those products ever shipped RIP 2.x support.

The Test Drive releases (2.00.01, 2.10.00, 2.11.00) have not been string-verified individually; given the 2.0-through-2.30 engines are identical in this respect, `RIPSCRIP020000` is presumed but unconfirmed for them.
