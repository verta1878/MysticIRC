# 5.3 Local File Playback

[◀ Prev: 5.2 Templates](5.2-templates.md) · [Contents](README.md) · [Next: 5.4 Pop-Up Lists ▶](5.4-popup-lists.md)

Local playback prefixes - `$>` for RIPscrip scenes, `$<` for BMP bitmaps, `$(` for JPEG images and `$)` for audio - replay a file already on the terminal's disk from inside any [host command](5.0-host-commands.md) or query.

_1.54 had only `$>file$`, for `.RIP` scenes - see [5.3 in the v1.54 reference](../../1.54/ripscrip/5.3-local-playback.md)._

## Local RIPscrip File Playback

You can re-play a .RIP file that you have locally on your hard disk from anyplace that allows [text variables](5.1-text-variables.md). The format of the variable is somewhat different than user variables, or pre-defined text variables. After the initial dollar sign (`$`), enter the greater-than symbol (`>`) followed by the filename (with or without the .RIP extension), then ending in another dollar sign (`$`). Several examples of this are as follows:

```text
$>MYFILE.RIP$
$>FILE1$
$>FILE1.RIP$$>FILE2.RIP$$>FILE3$
```

Note in the last example, a file extension other than .RIP was used. You are not limited to playing back local .RIP files. In fact, you can play-back any file you want. You could load any simple text file, ANSI picture image, or other such thing. When loaded, the data is not sent to the host; it is strictly echoed on your local screen. If the file is a .RIP file, it will replay any graphics that were in the file and if any Mouse Regions are defined, it will create those fields for you as well, thus allowing you to pop-up dialog screens or other such things that are not built-in to RIPterm normally.

Each "local RIP playback" variable you enter will search for the .RIP file in the current host's icon directory. If it cannot find the file in that directory, it will check the ICONS\ directory. Every playback prefix resolves filenames this way, connection directory first - see [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md#lookup-order-file-override).

## Local Audio File Playback

_Added in RIPscrip v2.A1._

In 2.0, we are introducing audio capability (both digitized and sequenced music). To further enhance our host command language, we are now offering an extension of local RIP file playback for audio files. This is "Local Audio File Playback". This command is nearly identical in syntax to the local RIP file playback command with a simple alteration. Instead of using the `>` character to signify RIPscrip file, you use the close paranthesis `)` as in the following example:

```text
$)AUDIOFILE.FIL$
$)TRAIN.WAV$
```

The file extension is unimportant. See the section of this document on [audio commands](4.5-audio-files.md) for more detailed information on audio.

## Local Bitmap Playback (Display)

_Added in RIPscrip v2.A1._

This command is much like the local RIPscrip playback or the local audio playback, but it intended to place a local bitmap (.BMP) file onto the screen. The bitmap will be displayed inside the current image settings as defined by the `RIP_IMAGE_STYLE` command and will adhere to the settings of that command. This mode of displaying a BMP file is the only method for showing a BMP via the image style settings.

For the purposes of universality, the bitmap is shown to the screen using the current screen's color palette and "auto-dithering" mode is used for the viewing of the image. If you need support for some of the other modes for viewing a bitmap image (ie, the [RIP_LOAD_BITMAP](4.0-icons-and-bitmaps.md#rip_load_bitmap)'s flexibility), then you will have to use that command instead. This command is provided as a simple method of showing a bitmapped image from within a host command.

Note, if no image style definition has been recorded then the bitmap is shown in the maximum size of the current viewport. In other words, it will be scaled to fill up the entire viewport.

To instruct the terminal to playback a local bitmap file, you would execute a host command with the following in it:

```text
$<FILENAME.BMP$
```

Note that this uses the less-than sign unlike the greater than sign used for local RIPscrip file playback. This is intentional. In fact, we use the opposite angle-bracket to indicate that this is a low-level primitive type playback like local RIPscrip file playback. The audio playback uses the parenthesis because it is not a low-level primitive playback, but a higher level concept. We use the parenthesis as a distinction from the lower level playback commands.

## Local Image File Playback (Display)

_Added in RIPscrip v2.A1._

This command is similar to the local bitmap playback except that dealing with raw bitmapped images, this command displays compressed photo-like images. Currently, only JPEG compressed image files are supported. This command takes a JPEG file and displays it based on the defined image style (set with a `RIP_IMAGE_STYLE`) command. If no image style is recorded, then the JPEG file is displayed inside the current viewport and will occupy the entire viewport's dimensions.

This command uses a syntax similar to the local bitmap playback operation but instead uses the `(` character instead of the `<` one. This uses the same idealogy as was noted between local RIPscrip file playback and local audio file playback. The JPEG file is considered a higher level object then a raw bitmap, so it uses the parenthesis command character instead of the angle brackets. To playback the local JPEG file MYFILE.JPG, issue the following command:

```text
$(MYFILE.JPG$
```

## Worked examples per prefix

**`$>file.rip$` - scene playback from a mouse field.** A mouse field whose host command is nothing but a playback variable displays a locally stored dialog scene when clicked - nothing is sent to the host:

```text
!|1M00051E1R2A1100000$>HELPBOX$
```

Clicking the region replays `HELPBOX.RIP` from the connection directory (or the default `ICONS\` directory). If `HELPBOX.RIP` itself defines mouse fields - say an "OK" button whose host command is `$PCB$` to paste back the screen area saved earlier - the pop-up is fully interactive without any host round-trip.

**`$(file.JPG$` - image display from a button.** A button that shows a locally cached photograph inside the current image area ([RIP_IMAGE_STYLE](4.1-jpeg-images.md#rip_image_style)) when clicked:

```text
!|1U0A0A00003200<>View photo<>$(SUNSET.JPG$
```

The image scales into the image area exactly as if the host had issued [RIP_IMAGE](4.1-jpeg-images.md#rip_image) - but with no transmission cost, because `SUNSET.JPG` was delivered earlier by block mode.

**`$)FILE.WAV$` - audio playback from a host command.** A host command (or portion of one) that starts background audio:

```text
$)TRAIN.WAV$Now boarding^m
```

The terminal starts `TRAIN.WAV` playing in the background and transmits `Now boarding` plus a carriage return to the host. `$)$OFF$` semantics for stopping playback belong to [RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio) - see [4.5 Audio Files](4.5-audio-files.md).

**Chained playback.** Several files can be replayed back-to-back from one command, as in `$>FILE1.RIP$$>FILE2.RIP$$>FILE3$` - useful for assembling a scene from locally cached parts.

## Playback prefixes vs dedicated commands

Same media, different invocation path: the chapter-4 commands live in the RIPscrip **command stream** (the host draws _now_, mid-scene), while the playback prefixes live at the **host-command/macro layer** (the action fires later, when a button or mouse field is clicked, or when a query is processed). The prefix forms also deliberately trade flexibility for brevity - fixed display settings where the commands take parameters.

| Media | Command-stream command | Host-command prefix | Differences |
| --- | --- | --- | --- |
| RIPscrip scene | [RIP_READ_SCENE](5.5-file-transfer-and-queries.md#rip_read_scene) | `$>file.rip$` | Same playback engine; the prefix form is the only one usable from a click |
| BMP bitmap | [RIP_LOAD_BITMAP](4.0-icons-and-bitmaps.md#rip_load_bitmap) / [RIP_LOAD_ICON](4.0-icons-and-bitmaps.md#rip_load_icon) | `$<file.BMP$` | The prefix displays via the image-style area with auto-dithering and the current palette only; the commands offer position, scaling, put modes, palette and transparency flags |
| JPEG image | [RIP_IMAGE](4.1-jpeg-images.md#rip_image) | `$(file.JPG$` | Both display via the current [RIP_IMAGE_STYLE](4.1-jpeg-images.md#rip_image_style) settings |
| WAV audio | [RIP_PLAY_AUDIO](4.5-audio-files.md#rip_play_audio) | `$)FILE.WAV$` | Both start background playback; the command form also defines `$OFF$` to stop a running sound |
