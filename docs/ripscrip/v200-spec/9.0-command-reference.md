# 9.0 Command Reference

[◀ Prev: 7.2 Data Backup Areas](7.2-data-backup-areas.md) · [Contents](README.md) · [Next: 9.1 Text Variable Reference ▶](9.1-text-variable-reference.md)

Every RIPscrip 2.x command with its [command level](../../glossary.md), command type character, argument summary, spec revision introduced, and one-line purpose, each symbol linked to its full entry.

Argument notation follows [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md#how-commands-are-documented): `name:width` fields are fixed-width numbers in the current [Base Math](../../glossary.md); `:XY` marks a variable-width coordinate (2 digits by default, adjustable via [RIP_SET_COORDINATE_SIZE](1.2-math-and-coordinates.md#rip_set_coordinate_size)); `:CM` marks a color parameter that follows the current color mode; `text` is a trailing text parameter; `...` marks variable-length commands; `<esc>` denotes the actual Escape character (ASCII 27). The **Added** column gives the spec revision that introduced the command - blank means carried from 1.54 or earlier.

## Announced but never specified

**RIP_FILE_DELETE** appears in the v2.A3 revision history ("to remove unneeded JPEG or WAVE files off the user's hard disk") but received no command entry, no opcode and no argument list, and the name is absent from every shipping binary. The capability shipped one revision later as the [`$FILEDEL(file,...)$`](9.1-text-variable-reference.md) text variable _(v2.A4)_, which every 2.x engine implements - use that. Details and evidence: [Errata](errata.md#rip_file_delete-was-announced-never-specified).
