# MicroANSI Delta (RIPscrip.maf)

[◀ Prev: FastFont Additions](3.2-fastfont-additions.md) · [Contents](README.md) · [Next: Connection Directory Model ▶](4.0-connection-directory-model-delta.md)

The MicroANSI container format - the fixed-cell **CP437** bitmap fonts behind the ANSI/VT-102 terminal emulation and text windows - is fully documented in the 2.0 techspec [MicroANSI Terminal Fonts (RIPTERM.FNT / .MAF)](../../2.0/techspecs/3.3-microansi-fonts.md). RIPtel 3.1 ships the same container as `FONTS/RIPscrip.maf` (270,945 bytes, dated 1997-04-18; md5 `f6513a02bd973c101d0d34119b721984`, byte-exact in [`version/3.0/assets/fonts/`](../../3.0/assets/fonts/README.md)) with the identical magic - still literally `\x04 RIPterm v2.0 MicroANSI Font File \x04\n\r\x00\x1a` - and the identical record formats.

All offsets below were verified programmatically against the shipped file; integers little-endian.

## Same formats, byte-verified

- **Container header:** magic at 0x00, u16 `resolutionCount` at 0x28 (= **6**, was 5), u32 `directoryOffset` at 0x2A (= **0x3C**), zero to 0x3C - identical field positions.
- **Resolution directory:** the same **60-byte** records - `u16 width, u16 height, u32 fontOffset[5], char name[36]` - verified two independent ways: the directory's 6 × 60 bytes end at 0x1A4, exactly the first font subrecord's offset, and a 64-byte/`name[40]` parse collapses immediately (the second record would read width 25,660, height 0, and a fifth "offset" of 0x78303038 - ASCII `800x` garbage). This corrects the [research triage §1](../../3.0/research/riptel-binary-formats.md), which described 64-byte records; a correction note now stands there.
- **Font subrecords:** the same layout - 50-byte header (`u16 cellWidth, u16 cellHeight, char name[30], u16 lastChar` = 0x00FF, `u16 bytesPerGlyph`, `byte[12]` reserved, observed zero) followed by **255 glyphs** of `bytesPerGlyph` bytes for characters 0x01-0xFF (character 0x00 is not stored and renders blank; see the corrected [2.0 subrecord section](../../2.0/techspecs/3.3-microansi-fonts.md#font-subrecords)). Verified: every one of the 30 fonts ends at exactly `offset + 50 + 255 × bytesPerGlyph`, which is the next font's offset or end-of-file; the CP437 smiley (char 0x01) opens the 8×11 font's glyph data at 0x1A4 + 50 = 0x1D6 with `7E 81 A5 A5 81 81 BD 99 81 81 7E`. For the three resolutions shared with RIPterm 2.30, all 15 subrecord headers are **byte-identical** to the RIPterm 2.30 `RIPTERM.MAF` headers.

## The new resolution set

The RIPtel directory (at 0x3C):

| Record | Resolution | Name | Cell sizes (80×43, 91×43, 80×25, 91×25, 40×25) | First offset |
| --- | --- | --- | --- | --- |
| 0 | 640×480 | `640x480 VGA` | 8×11, 7×11, 8×19, 7×19, 16×19 | 0x1A4 |
| 1 | 800×600 | `800x600 - VGA` | 10×13, 8×13, 10×24, 8×24, 20×24 | 0x643C |
| 2 | 1024×768 | `1024x768 - VGA` | 12×17, 11×17, 12×30, 11×30, 20×24 | 0x11B7F |
| 3 | 639×479 | `Small 640x480` | 7×10, 6×10, 7×18, 6×18, 14×18 | 0x21F75 |
| 4 | 799×599 | `799x599` | 9×12, 8×12, 9×21, 8×21, 18×21 | 0x27C13 |
| 5 | 1023×767 | `1023x767` | 12×16, 11×16, 12×28, 11×28, 24×28 | 0x31E6B |

Versus the RIPterm 2.30 container: **dropped** `640x350 EGA` (RIPtel is a Windows program; no EGA text modes) and the never-reachable `1280x1024` set; **kept** the three VGA/SVGA sets with identical cell sizes - including the 1024×768 quirk of a 20×24 fifth font (the 40×25 mode font is not scaled up at that resolution, exactly as in RIPterm 2.30); **added** three sets at one-pixel-short dimensions (639×479, 799×599, 1023×767) plus smaller-celled "Small" fonts. The obvious reading - cells sized to fit a client area slightly smaller than the nominal resolution, i.e. RIPtel's windowed display - is _interpretation, not verified_ against the renderer; the five cell heights per set still map to the five text modes (80×43, 91×43, 80×25, 91×25, 40×25 - MESSAGES.HLP lists exactly these, [help extraction §9](../../3.0/research/riptel-help-extraction.md)).

## Layout hygiene - one directory, no leftovers

The RIPterm 2.30 container's construction quirks are gone. `directoryOffset` = 0x3C points at a **single directory immediately after the header**; there are no stale directory snapshots between resolution blocks (RIPterm 2.30 carried four progressively longer copies, only the last valid - see the corrected [2.0 directory caveat](../../2.0/techspecs/3.3-microansi-fonts.md#container-layout)), the 30 fonts are packed back-to-back in directory order, and the file ends exactly where the last font ends (0x3CE83 + 50 + 255 × 84 = 0x42261 = file length). Parsers should still follow the u32 at 0x2A rather than assume 0x3C.

## The artwork revision

RIPscrip.maf is a **third revision** of the shared glyph artwork (after RIPterm 2.0's `RIPTERM.FNT` and RIPterm 2.30's `RIPTERM.MAF`). Comparing the 15 shared fonts glyph-by-glyph against RIPterm 2.30's `RIPTERM.MAF`:

| Font | Changed glyphs vs RIPterm 2.30 `.MAF` | Character range touched |
| --- | --- | --- |
| 640×480 8×11 | 42 | 0xB0-0xDA (box/block drawing) |
| 640×480 7×11 | 22 | 0xB0-0xDB |
| 640×480 8×19 | 229 of 255 | 0x03-0xFE (wholesale redraw) |
| 640×480 7×19 | 40 | 0xB0-0xDA |
| 640×480 16×19 | 42 | 0xB0-0xDA |
| 800×600 10×13 | 22 | 0xB0-0xDA |
| 800×600 8×13 | 23 | 0xB0-0xDA |
| 800×600 10×24 | 230 of 255 | 0x01-0xFE (wholesale redraw) |
| 800×600 8×24 | 21 | 0xB0-0xDA |
| 800×600 20×24 | 44 | 0x39-0xDA |
| 1024×768 12×17 | 22 | 0xB0-0xDA |
| 1024×768 11×17 | 43 | 0xB0-0xDA |
| 1024×768 12×30 | 250 of 255 | 0x01-0xFE (wholesale redraw) |
| 1024×768 11×30 | 45 | 0x3A-0xDA |
| 1024×768 20×24 | 254 of 255 | 0x01-0xFE (wholesale redraw) |

The pattern: most fonts got a **box-drawing/block-character cleanup** (0xB0-0xDA - the CP437 shade and line-drawing range), while the four primary-mode fonts (the 80×25 fonts at each resolution, plus the 40×25 font) were **redrawn nearly in full**; no shared font is byte-identical to either the RIPterm 2.0 or the RIPterm 2.30 artwork. Worked example, 640×480 8×11 font: the box-drawing strokes were thickened from one pixel to two - char 0xC5 (┼) changes from rows of `10` with a one-row `FF` crossbar to rows of `30` with a two-row crossbar, and char 0xD9 (┘) likewise `10…F0` → `30…F0 F0`; char 0xB0 (░ light shade) trades RIPterm 2.30's half-empty `AA 00 55 00` dither for a denser `88 22` pattern (glyph bytes at `fontOffset + 50 + (char - 1) × 11` in each file).

The six new resolution sets (records 3-5) have no RIPterm 2.30 counterpart to diff against; their artwork is original to this file.
