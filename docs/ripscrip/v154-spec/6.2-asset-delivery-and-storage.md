# 6.2 Asset Delivery & Storage

[◀ Prev: 6.1 Content File Roles](6.1-content-file-roles.md) · [Contents](README.md) · [Next: 9.0 Command Reference ▶](9.0-command-reference.md)

How a host delivers content files to the terminal and where they land: the query-then-download workflow, the per-host connection directory, the shared default icon directory, and the file override lookup order.

## The delivery workflow

A well-behaved host delivers assets in two steps:

1. **Staleness check** - [RIP_FILE_QUERY](5.5-queries-and-advanced-commands.md#rip_file_query) asks whether a file already exists on the terminal's disk, and its size (mode 02) or size, date and time (modes 03-04). The host compares the response against its own copy to decide whether a download is needed at all - avoiding re-sending files the terminal already has.
2. **Download** - [RIP_ENTER_BLOCK_MODE](5.5-queries-and-advanced-commands.md#rip_enter_block_mode) auto-initiates a file transfer (Xmodem variants, Kermit, Ymodem, Ymodem-G, or Zmodem) with a file-type code telling the terminal what it is receiving: `.RIP` scenes to display or store, `.ICN` sequences to store in the proper directories, `.HLP` files, or DYNAMIC batch sequences processed by extension.

Once delivered, the host can use the assets by name - stamping icons ([RIP_LOAD_ICON](4.0-images-and-icons.md#rip_load_icon)), replaying scenes ([RIP_READ_SCENE](5.5-queries-and-advanced-commands.md#rip_read_scene), or `$>file$` playback variables in host commands, [5.3 Local File Playback](5.3-local-playback.md)) - with no further transmission cost.

Uploads work through the same block-mode command with mode 1; the user can be prompted to authorize them (Data Security), and an unauthorized upload is refused with ten CAN (Ctrl-X) characters.

## Where files land

RIPterm's dialing directory associates an optional per-host sub-directory with each entry - the **DIR field** - auto-created on first use. This is the host's [connection directory](../../glossary.md):

- When a connection directory is configured for the current host, host-delivered files (icons, scenes, help files) are stored **there**.
- When none is configured, files land in the shared [default icon directory](../../glossary.md) (`ICONS\`).

## Lookup order ("file override")

When a command or playback variable references a file by name, the terminal searches the **connection directory first**, then falls back to the default `ICONS\` directory. (This is stated for local playback in the 1.54 spec itself - see [5.3 Local File Playback](5.3-local-playback.md).)

The point of this two-level scheme is that same-named assets from different hosts do not collide: each host's `MENU.ICN` resolves to that host's own copy, while genuinely shared assets can live once in `ICONS\`. The RIPterm manuals call this behavior "[file override](../../glossary.md)".

Commands never carry path information - filenames are bare DOS-style names, and the terminal decides where they resolve. (Modern implementations should also treat lookups as case-insensitive, as the DOS/Windows originals inherently were - see the [connection directory model techspec](../techspecs/4.0-connection-directory-model.md).)
