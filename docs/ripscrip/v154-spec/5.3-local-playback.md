# 5.3 Local File Playback

[◀ Prev: 5.2 Host Command Templates](5.2-host-command-templates.md) · [Contents](README.md) · [Next: 5.4 Pop-Up Lists ▶](5.4-popup-lists.md)

The `$>file$` [text variable](5.1-text-variables.md) form replays a `.RIP` - or any other - file already on the terminal's disk, from anywhere text variables are allowed.

_The host-driven equivalent command is [RIP_READ_SCENE](5.5-queries-and-advanced-commands.md#rip_read_scene)._

You can re-play a .RIP file that you have locally on your hard disk from anyplace that allows [text variables](5.1-text-variables.md). The format of the variable is somewhat different than user variables, or pre-defined text variables. After the initial dollar sign (`$`), enter the greater-than symbol (`>`) followed by the filename (with or without the .RIP extension), then ending in another dollar sign (`$`). Several examples of this are as follows:

```text
$>MYFILE.RIP$
$>FILE1$
$>FILE1.RIP$$>FILE2.RIP$$>FILE3$
```

Note in the last example, a file extension other than .RIP was used. You are not limited to playing back local .RIP files. In fact, you can play-back any file you want. You could load any simple text file, ANSI picture image, or other such thing. When loaded, the data is not sent to the host; it is strictly echoed on your local screen. If the file is a .RIP file, it will replay any graphics that were in the file and if any Mouse Regions are defined, it will create those fields for you as well, thus allowing you to pop-up dialog screens or other such things that are not built-in to RIPterm normally.

Each "local RIP playback" variable you enter will search for the .RIP file in the current host's icon directory (the [connection directory](../../glossary.md)). If it cannot find the file in that directory, it will check the `ICONS\` directory. (This is the standard [file override](../../glossary.md) lookup order - see [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md).)

## Worked examples of the host-command flow

> **Editor's note:** this section is an editor's addition and does not appear in the original 1.54 document; every mechanism it uses is defined elsewhere in this reference.

Local playback shines inside [host commands](5.0-host-commands.md): because a `$>file$` variable expands wherever text variables do, a [mouse field](4.1-mouse-fields.md) or [button](4.2-buttons.md) click can replay a locally stored scene instantly - no re-transmission over the modem. Each example below uses only mechanisms documented in this reference.

**Pop-up dialog from a mouse field.** A mouse field whose host command is nothing but a playback variable displays a locally stored dialog scene when clicked - nothing is sent to the host:

```text
!|1M00051E1R2A1100000$>HELPBOX$
```

Clicking the region replays `HELPBOX.RIP` from the connection directory (or `ICONS\`). If `HELPBOX.RIP` itself defines mouse fields (e.g. an "OK" button whose host command is `$PCB$` to restore the screen area saved earlier), the pop-up is fully interactive.

**Combining playback with a host command.** Playback variables mix freely with ordinary host-command text. A button that both replays a local "please wait" scene and then tells the host to proceed could carry:

```text
$>WAITSCRN$R^m
```

The terminal echoes `WAITSCRN.RIP` locally, then transmits `R` and a carriage return to the host.

**Chained playback.** Several files can be replayed back-to-back from one command, as in the `$>FILE1.RIP$$>FILE2.RIP$$>FILE3$` example above - useful for assembling a scene from locally cached parts.

A host typically pairs this mechanism with [RIP_FILE_QUERY](5.5-queries-and-advanced-commands.md#rip_file_query) (to check the file exists and is current) and a block-mode download if it is missing - that delivery workflow is worked through in [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md).
