# 9.0 Command Reference

[◀ Prev: 7.2 Data Backup Areas](7.2-data-backup-areas.md) · [Contents](README.md) · [Next: 9.1 Text Variable Reference ▶](9.1-text-variable-reference.md)

_Reconstructed edition - every claim carries an evidence tag; see [Contents](README.md) for the legend._

Every command of the reconstructed RIPscrip 3.x inventory with its [command level](../../glossary.md), command type character, argument summary, lineage/evidence status, and one-line purpose, each symbol linked to its full entry.

Argument notation follows [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md#how-commands-are-documented): `name:width` fields are fixed-width numbers in the current [Base Math](../../glossary.md); `:XY` marks a variable-width coordinate (2 digits by default, adjustable via [RIP_SET_COORDINATE_SIZE](1.2-math-and-coordinates.md#rip_set_coordinate_size)); `:CM` marks a color parameter that follows the current color mode; `text`/`filename` is a trailing text parameter; `...` marks variable-length commands; `<esc>` denotes the actual Escape character (ASCII 27).

TeleGrafix never published a 3.x language reference, so this inventory is an editorial reconstruction assembled from the 2.00 ALPHA 4 specification, the RIPSCRIP.HLP command-name inventory (~90 `RIP_*` names recovered from the RIPtel 3.1 help files and DLL string tables), the 116-script RIPtel demo corpus, and SyncTERM's open-source RIP 3.0 implementation - the **Added/Status** column carries both lineage and evidence status per the legend below.

**Added/Status legend:**

- blank - carried from 1.54 or earlier into the 2.0 engine that 3.x inherits.
- `v1.54`, `v2.A0`-`v2.A4` - spec revision that introduced the command (2.00 ALPHA draft revisions; 3.x inherits the 2.0 engine).
- `3.0 (corpus)` - 3.x-era command recovered from the RIPtel demo-script census; documented in no published specification.
- `3.0 (HLP; corpus)` - 3.x-era command attested by the RIPSCRIP.HLP name inventory and the corpus, absent from the 2.00a4 draft.
- `HLP only` - named in the RIPSCRIP.HLP command-name inventory but with no observed wire syntax, no known opcode, and no implementation; listed unlinked (no full entry exists).
- `SyncTERM only` - known only from SyncTERM's descriptor table or source code; no spec, HLP, or corpus attestation; listed unlinked where no full entry exists.
- `deprecated v2.A2` - deprecated in that revision; still implemented by every shipping driver, so authors should avoid it and implementers still have to handle it. The linked page explains why.
- `obsolete v2.A1` - declared obsolete in that revision but still parsed by clients.
- (\*), (†), (‡), (§), (¶) - footnotes for special cases, listed [at the end of the page](#footnotes).

## Footnotes

- (\*) The 2.00a4 draft assigns letter `b` to **both** RIP_SET_BASE_MATH and RIP_EXTENDED_TEXT_WINDOW - an unresolved collision in the draft. The shipping 3.0 driver moved base math to **`J`** (90 of 116 corpus files open with `!|J10|n2000|M08|fZKQO`, and ONLINE.RIP annotates `J10` inline as "Set base math to MegaNums"), leaving `b` to the extended text window, exactly as SyncTERM's descriptor table also has it. _Evidence: corpus; SyncTERM._
- (†) The command name is an editorial hypothesis reconstructed from census evidence (demo comments, on-screen titles, or layout analysis); TeleGrafix's own name is unrecovered. The six skewed-oval names, by contrast, come verbatim from TeleGrafix's NEWCMDS.RIP comments and are not so marked; RIP_POLY_POLYGON's name is taken from its demo's own on-screen title _(hypothesis)_.
- (‡) The RIPSCRIP.HLP inventory lists this command under the 3.0 name `RIP_BeginEncodedStream`, and its error strings reference "encoded stream" file types - the mechanism survived into 3.x under the new name.
- (§) For `HLP only` names the level shown is inferred from the name's grouping in the RIPSCRIP.HLP inventory _(hypothesis)_; no opcode, wire syntax, or implementation is recovered, so these rows are unlinked (no full entry exists in this reference).
- (¶) The 3.x wire layout of RIP_EXTENDED_FONT_STYLE (26 fixed digits + font name, per TeleGrafix's crib `!|!sfFFFFZZOOSSCCBBCCWWRRRRRR` in FONTS.RIP) does **not** match the 2.00a4 draft's 13-character argument list, and field roles beyond the crib are _(hypothesis)_ - see the full entry. The rework predates 3.x: RIPterm Professional 2.0's SHADOW.RIP already drives `y` with the 26-character block.

## Announced but never specified

**RIP_FILE_DELETE** appears in the 2.00a4 v2.A3 revision history ("to remove unneeded JPEG or WAVE files off the user's hard disk") but received no command entry, opcode or argument list, and no such command name appears in the RIPSCRIP.HLP inventory. The capability is implemented as a text variable instead: `RIPSCRIP.HLP` carries the handler symbol `tvarProcFILEDEL` (the `tvarProc` prefix marking a text-variable processor), and `FILEDEL` is present in the shipping RIPterm 2.0/2.20.01/2.30 executables. Hosts use [`$FILEDEL(file,…)$`](9.1-text-variable-reference.md); see [5.5](5.5-file-transfer-and-queries.md). _Evidence: 2.00a4; HLP._
