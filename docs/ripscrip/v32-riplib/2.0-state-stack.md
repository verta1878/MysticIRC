# 2.0 Drawing State Stack - `|^` / `|~` (§A2G.8)

[◀ Prev: Contents](README.md) · [Contents](README.md) · [Next: 2.1 Radial Gradient ▶](2.1-radial-gradient.md)

_Covers RIPlib §A2G.8. Two new Level-0 commands. See the [tree README](../README.md) for standing and provenance._

Scenes re-send the same prelude constantly - set color, set fill, set line style, draw, set it all back. §A2G.8 adds a bounded LIFO stack so a scene can save that prelude, change it freely, and restore it in two characters.

## RIP_PUSH_STATE

_Push the current drawing state onto the state stack_

|               |          |
| ------------- | -------- |
| **Level**     | 0        |
| **Command**   | `^`      |
| **Arguments** | _(none)_ |

**Format:** `!|^`

## RIP_POP_STATE

_Restore the most recently pushed drawing state_

|               |          |
| ------------- | -------- |
| **Level**     | 0        |
| **Command**   | `~`      |
| **Arguments** | _(none)_ |

**Format:** `!|~`

## What a frame holds

Each frame captures the fields a scene most often re-sends as a prelude before a styled draw: `A2G.8`

| Group | Fields |
| --- | --- |
| Color | draw color, background color, fill color |
| Fill & line | fill pattern, line style, line pattern (the full 16-bit custom pattern), line thickness, write mode |
| Filled objects | filled-borders enabled ([RIP_SET_BORDER](../../3.0/ripscrip/2.3-shapes-and-fills.md#rip_set_border) state) |
| Stroke font | font ID, size, direction, attributes, horizontal justification, vertical justification |
| Extended font | extended font ID, attributes, size |
| Position | drawing cursor X, Y |
| Viewport | `vp_x0`, `vp_y0`, `vp_x1`, `vp_y1` |

It does **not** capture the framebuffer, the palette, mouse fields, text windows, icons, or the port table - this is drawing _state_, not screen contents.

## Bounds and behavior

- **Depth is capped at 8 frames** (`RIP_STATE_STACK_MAX`). `A2G.8`
- **Push on a full stack is silently dropped** - deliberately following the language's "ignore what you don't understand" precedent for graceful degradation rather than raising an error. `A2G.8` A scene that nests deeper than 8 therefore pops mismatched state rather than failing loudly; keep nesting shallow.
- **Pop on an empty stack is a no-op.** `A2G.8`
- **A successful pop re-applies the full drawing state immediately**, so the next drawing command picks up the restored color, write mode, line, fill, cursor and viewport - not at some later flush. `A2G.8`
- **The stack resets to depth 0** on [RIP_RESET_WINDOWS](../../3.0/ripscrip/1.3-world-view-virtual-canvas.md#rip_reset_windows) (`|*`) and on a host-driven session reset. `A2G.8` Since `!|*` opens nearly every scene ([1.54 prologue conventions](../../1.54/techspecs/1.0-rip-stream-parsing.md#scene-prologue-and-epilogue-conventions)), a stack cannot leak across scenes.

## Example

```text
!|c04|S0204|       red outline, green fill
!|^|               push
!|c0F|S0104|       white outline, blue fill
!|R0A0A1414|       blue-filled rect with a white border
!|~|               pop - back to red outline, green fill
!|R28281414|       another rect, original colors
```

`A2G.8`

## Relationship to the TeleGrafix record

**The command letters are free.** Neither `^` nor `~` is assigned in the 1.54, 2.00a4 or reconstructed 3.x command inventories ([3.0 command reference](../../3.0/ripscrip/9.0-command-reference.md)), so `|^` and `|~` are clean additions and a 3.0 terminal discards them as unknown commands. What it will _not_ do is restore state, so a scene using the stack renders in whatever colors it last set - visually wrong rather than broken.

**The need is real and the record's answer is heavier.** RIPscrip 2.x/3.x does have state save/restore, but at table granularity through the [data backup areas](../../3.0/ripscrip/7.2-data-backup-areas.md) and text variables: `$SGS(dest)$` / `$RGS(source)$` save and restore the **graphics style table** - the same prelude fields - to and from a backup area, with parallel pairs for the color palette (`$SCP$`/`$RCP$`), button styles (`$SBS$`/`$RBS$`), text windows (`$STW$`/`$RTW$`), mouse fields (`$SMF$`/`$RMF$`) and environments (`$SENV$`/`$RENV$`), plus `$SAVEALL$` / `$RESTOREALL$` over the lot ([3.0 variable reference](../../3.0/ripscrip/9.1-text-variable-reference.md)). And `$STW(PUSH)$` / `$RTW(POP)$` show the language already knew the stack idiom - it just applied it to the text-window table rather than the drawing prelude. [RIP_SWITCH_STYLE](../../3.0/ripscrip/7.1-data-tables.md#rip_switch_style) (`|2Y`) switching among 36 graphical style entries covers much of the same ground from a different angle.

So §A2G.8 is not filling a gap so much as offering a cheaper, unparameterized instrument for the common case - two bytes on the wire against a text-variable expansion plus a backup-area slot. That is a defensible design, but a host targeting both would be better served by `$SGS$`/`$RGS$`, which works on shipping 3.x terminals today.
