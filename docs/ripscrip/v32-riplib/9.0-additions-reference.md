# 9.0 Additions Reference (v3.2 / §A2G.8-13)

[◀ Prev: 5.0 `<<DEBUG>>` Directive](5.0-debug-directive.md) · [Contents](README.md) · [Next: 9.1 Text Variables ▶](9.1-text-variables.md)

_Every language-visible difference between RIPlib's v3.2 and its v3.1 baseline, in one place, each cross-checked against the record reconstructed in this repository. See the [tree README](../README.md) for standing and provenance._

Classification: **Addition** (no counterpart here, degrades cleanly on an older terminal) · **Duplicate** (the record provides the same value or effect under another name) · ⚠ **Conflict** (an existing name or field given a different meaning).

## Version identification

|  |  |
| --- | --- |
| **Wire string** | `RIPSCRIP032001` - `RIPSCRIP` + major `03` + minor `20` + sub `01` |
| **Reported by** | `$RIPVER$` and the `ESC[!` auto-sense response `spec (01 §1.7, 07 §7.3)` |
| **Predecessors** | `RIPSCRIP031001` ([v3.1](../../3.1-riplib/ripscrip/9.0-additions-reference.md)) · `RIPSCRIP030001` (SyncTERM's 3.0 mode) · `RIPSCRIP015400` (1.54) - see the [3.0 versions reference](../../3.0/ripscrip/9.2-versions.md) |

Hosts that prefix-match `RIPSCRIP03` (the guidance in the 3.0 versions reference, since RIPtel's exact reply is unrecovered) treat `RIPSCRIP032001` as a 3.x terminal, which is the right outcome.

## Commands and directives

| Command | Change | Class | Detail |
| --- | --- | --- | --- |
| `\|^` | New Level-0 command, no arguments - push drawing state | **Addition** | `^` is unassigned as a command letter in the 1.54, 2.00a4 and 3.x inventories. [2.0 State Stack](2.0-state-stack.md) |
| `\|~` | New Level-0 command, no arguments - pop drawing state | **Addition** | `~` likewise unassigned. [2.0 State Stack](2.0-state-stack.md) |
| `\|28` | `mode` value `2` - radial gradient | **Addition** _(to a command not in the record)_ | The mode value is a clean addition; ⚠ the gradient command itself is part of RIPlib's v3.0 baseline and is unattested in the TeleGrafix record. [2.1 Radial Gradient](2.1-radial-gradient.md) |
| `<<DEBUG msg>>` | New preprocessor directive - emits `>DEBUG: <msg>` + CR to the host | **Addition** | Slots into the real 3.x `<<…>>` macro layer; ⚠ can shadow a `<<NAME>>` macro, and unsolicited terminal-to-host traffic has no precedent in the protocol. [5.0 `<<DEBUG>>` Directive](5.0-debug-directive.md) |

No existing command's wire format changes - the compatibility contract RIPlib states for v3.2 holds on the command side.

## Text variables

Thirty-one new names in three groups, covered in full with per-name analysis in [9.1 Text Variables](9.1-text-variables.md). Summary:

| Group | Count | Additions | Duplicates | Conflicts |
| --- | --- | --- | --- | --- |
| §A2G.9 layout / introspection | 9 | 7 | 2 (`$VPW$`, `$VPH$` - see `$PORTW$` / `$PORTH$`) | 0 |
| §A2G.10 time components | 6 | 0 | 3 (`$MIN$`, `$SEC$` agree; `$DOM$` = `$DAY$`) | **3** (`$HOUR$`, `$DOW$`, `$MONTH$`) |
| §A2G.11 EGA color names | 16 | 16 | 0 | 0 |

The three §A2G.10 conflicts are the substantive interoperability issue in v3.2, and they are cheap to fix: the record already names every value RIPlib wants (`$MHOUR$` for 00-23, `$WDAY$` for the 0-6 day number, `$MONTHNUM$` for 01-12, `$DAY$` for day of month), so adopting those names would clear the group entirely.

## Where v3.2 stands against v3.1

v3.1's additions changed how existing commands behave - write-mode numbers, text direction, font attributes, palette placement - and several collided with the documented record. v3.2 is markedly more conservative on the command side: two unused command letters, one new value in one field, one new directive. The variable groups repeat the v3.1 pattern of taking established names for new meanings, and that is the part worth resolving before the two efforts converge.
