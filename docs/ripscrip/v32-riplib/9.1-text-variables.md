# 9.1 Text Variables (§A2G.9, §A2G.10, §A2G.11)

[◀ Prev: 9.0 Additions Reference](9.0-additions-reference.md) · [Contents](README.md)

_Covers RIPlib §A2G.9 through §A2G.11 - thirty-one new variable names in three groups, each checked against the roughly 120-entry [canonical 3.x inventory](../../3.0/ripscrip/9.1-text-variable-reference.md). See the [tree README](../README.md) for standing and provenance._

All three groups expand wherever `rip_expand_variables` runs - `|T`, `|@`, `|t`, `|"` and `|-` text bodies, and `<<IF>>` expression bodies. They do **not** expand inside numeric command-argument fields such as `|c<color>`, because those are read directly from the wire buffer before variable expansion is reached. `A2G.11`

Classification used below: **Addition** (no counterpart in the record) · **Duplicate** (the record already provides the value under another name) · ⚠ **Conflict** (the name exists in the record with a different meaning).

## §A2G.9 - Layout and introspection

Read-only accessors for current drawing state, each expanding to a decimal string suitable for direct comparison in `<<IF>>`. `A2G.9`

| Variable | Expands to | Class | Notes |
| --- | --- | --- | --- |
| `$CX$` | Current draw cursor X | **Addition** | The record's `$CURX(win)$` is the _text_ cursor; `$TEXTXY$` gives the last graphical text position. No graphics-cursor query exists |
| `$CY$` | Current draw cursor Y | **Addition** | as above |
| `$VPW$` | Viewport width, `vp_x1 - vp_x0 + 1` | **Duplicate** | `$PORTW(port,domain)$` - width of a port, renamed from 1.54's `$VIEWX$` in 2.A4 |
| `$VPH$` | Viewport height, `vp_y1 - vp_y0 + 1` | **Duplicate** | `$PORTH(port,domain)$`, renamed from `$VIEWY$` |
| `$VPCX$` | Viewport center X, `(vp_x0 + vp_x1) / 2` | **Addition** | Computable from `$PORTX0$` / `$PORTX1$`, but not provided directly |
| `$VPCY$` | Viewport center Y | **Addition** | as above |
| `$CCOL$` | Current draw color, 0-15 | **Addition** | The record has `$COLORS$` (device color count) but no current-color query |
| `$CFCOL$` | Current fill color, 0-15 | **Addition** |  |
| `$CBCOL$` | Current background color, 0-15 | **Addition** |  |

The motivating use is self-centering content - `!|@$VPCX$$VPCY$Hello, world|` survives `|v` viewport changes and `|2P` port definitions without the host hard-coding 320,200. `A2G.9` That is a genuine gap: the record's port variables are parameterized and return a named port's geometry, so "the current viewport, whatever it is" takes more work to express.

The two duplicates are worth flagging only because they are unparameterized. `$PORTW(port,domain)$` takes a port number _and_ a coordinate domain (world or device); `$VPW$` takes neither, so it cannot express "port 3's width in world coordinates". For its intended use - centering in the current port on a device-coordinate renderer - that is a fair simplification.

## §A2G.10 - Time components

⚠ **This group has the most collisions in either revision.** Every one of the six names exists in the record already; four carry a different meaning, and the record's names for RIPlib's meanings are all taken by other variables. `A2G.10`

| Variable | RIPlib v3.2 | The record ([3.0](../../3.0/ripscrip/9.1-text-variable-reference.md), [1.54](../../1.54/ripscrip/9.1-text-variable-reference.md)) | Class |
| --- | --- | --- | --- |
| `$HOUR$` | `HH`, **00-23** | `HH`, **01-12** (non-military). The 00-23 form is `$MHOUR$` | ⚠ **Conflict** |
| `$MIN$` | `MM`, 00-59 | `MM`, 00-59 | Duplicate _(agrees)_ |
| `$SEC$` | `SS`, 00-59 | `SS`, 00-59 | Duplicate _(agrees)_ |
| `$DOW$` | Digit **0-6, Monday = 0** | Day of week **fully spelled out** (`Monday`). The 0-6 form is `$WDAY$` - and it is **0 = Sunday** | ⚠ **Conflict** _(twice over - type and origin)_ |
| `$DOM$` | `DD`, day of month | Day of month is `$DAY$`, 01-31 | **Duplicate** _(new name for an existing value)_ |
| `$MONTH$` | `MM`, 01-12 | **Full month name** (`December`). The 01-12 form is `$MONTHNUM$` | ⚠ **Conflict** |

The failure mode is quiet. `<<IF $DOW$=4>>Happy Friday!<<ENDIF>>` - RIPlib's own example `A2G.10` - is false on every conforming 3.x terminal, where `$DOW$` expands to `Friday`; and if a host instead writes `<<IF $DOW$="Friday">>` for the record's semantics, it is false on RIPlib. Neither errors. The same applies to `$MONTH$` in any string a scene displays: `December` on one terminal, `12` on the other.

Nothing about the six values is objectionable - they are all things a scene wants - and the record supplies every one of them under a name of its own (`$MHOUR$`, `$WDAY$`, `$DAY$`, `$MONTHNUM$`). Adopting those names upstream would remove the whole group's conflict surface at no cost to the feature.

Two implementation notes that carry over cleanly: all six fall back to the local real-time clock when the host has not yet synced date/time, and `$DOW$` reuses the ISO-week arithmetic behind `$WOYM$`, so day-of-week and week-of-year stay consistent across leap years. `A2G.10` The record's `$WOYM$` (Monday-first week of year) sits alongside `$WOY$` (Sunday-first), which is the same Monday/Sunday split `$DOW$` and `$WDAY$` disagree on - so a conforming implementation needs both origins anyway.

## §A2G.11 - EGA color-name aliases

Sixteen readable aliases for the EGA palette indices, each expanding to its 2-digit MegaNum value. `A2G.11` **All sixteen are additions** - no name in the group appears in the 1.54, 2.00a4 or 3.x inventories.

| Index | Variable | Expands to |  | Index | Variable | Expands to |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | `$BLACK$` | `00` |  | 8 | `$DARKGRAY$` | `08` |
| 1 | `$BLUE$` | `01` |  | 9 | `$LIGHTBLUE$` | `09` |
| 2 | `$GREEN$` | `02` |  | 10 | `$LIGHTGREEN$` | `0A` |
| 3 | `$CYAN$` | `03` |  | 11 | `$LIGHTCYAN$` | `0B` |
| 4 | `$RED$` | `04` |  | 12 | `$LIGHTRED$` | `0C` |
| 5 | `$MAGENTA$` | `05` |  | 13 | `$LIGHTMAGENTA$` | `0D` |
| 6 | `$BROWN$` | `06` |  | 14 | `$YELLOW$` | `0E` |
| 7 | `$LIGHTGRAY$` | `07` |  | 15 | `$WHITE$` | `0F` |

The names and index assignments match the standard EGA palette as documented for [RIP_COLOR](../../3.0/ripscrip/2.0-color-modes-and-palettes.md#rip_color) - `$BROWN$` for index 6 rather than "dark yellow", `$LIGHTGRAY$`/`$DARKGRAY$` for 7 and 8 - so nothing here surprises.

**Their usefulness is narrower than it looks.** Because expansion does not reach numeric argument fields, `!|c$RED$` does _not_ set the color - the parser reads `$R` as a MegaNum before expansion happens. §A2G.11 is explicit about this. `A2G.11` What remains is text bodies and `<<IF>>` comparisons:

```text
!|TYour color is $LIGHTRED$|
<<IF $CCOL$=12>>The current color is light red<<ENDIF>>
```

Note that the second example compares `$CCOL$` (decimal, per §A2G.9) against a decimal literal, not against `$LIGHTRED$` (which is the MegaNum `0C`) - the two representations do not interoperate in a comparison. Aliases are for readability in the branch text, not for building command arguments.
