# 9.0 Additions Reference (v3.1 / §A2G.1-7)

[◀ Prev: 7.0 Port Flags](7.0-port-flags.md) · [Contents](README.md) · [Next: Technical Specifications ▶](../techspecs/README.md)

_Every language-visible difference between RIPlib's v3.1 and its v3.0 baseline, in one place, each cross-checked against the record reconstructed in this repository. See the [tree README](../README.md) for standing and provenance._

Each row is classified: **Addition** (no counterpart here, degrades cleanly on a 3.0 terminal) · **Redefinition** (an existing field or name given different meaning) · **Already documented** (present in the TeleGrafix record; new only to RIPlib).

## Version identification

|  |  |
| --- | --- |
| **Wire string** | `RIPSCRIP031001` - `RIPSCRIP` + major `03` + minor `10` + sub `01` |
| **Reported by** | `$RIPVER$` and the `ESC[!` auto-sense response `spec (01 §1.7, 07 §7.3)` |
| **Compare** | `RIPSCRIP015400` (1.54) · `RIPSCRIP030001` (SyncTERM's 3.0 mode) · `RIPSCRIP03000` (quoted in the RIPtel help files) - see [3.0 versions reference](../../3.0/ripscrip/9.2-versions.md) |

The 14-character layout is consistent with the 3.0 strings already on record, and `031001` sorts after `030001`, so a host doing prefix or numeric comparison degrades sanely. Note that RIPlib's field description reads the minor field as tenths (`10` → `.1`, `54` → `.54`), which is how `031001` denotes "3.1".

## Commands

| Command | Change | Class | Detail |
| --- | --- | --- | --- |
| `\|2F` | New Level-2 command - `port:1 [alpha:1] [comp_mode:2] [zorder:2]` | **Addition** | Level-2 letter `F` is unassigned in the 3.x record, so this is a clean addition. [7.0 Port Flags](7.0-port-flags.md) |
| `\|W` | `mode` values `02` (AND) and `04` (NOT) | **Already documented** | AND and NOT exist since 2.00 Alpha 1; what §A2G.1 adds is rendering them, which the DLL never did. The numbering conflict that comes with it is a baseline question - [3.0-riplib → write mode numbering](../../3.0-riplib/ripscrip/2.0-write-modes.md). [2.0 Write Modes](2.0-write-modes.md) |
| `\|Y` | `direction` value `02` (vertical, CCW glyph rotation) | **Addition** | `02` is undefined in the TeleGrafix record; values above `02` are rejected outright. [3.0 Text Direction](3.0-text-direction-and-font-attributes.md#text-direction---a-third-value-and-a-redefined-second) |
| `\|Y` | `direction` value `01` now renders **top to bottom** | **Redefinition** | 1.54 defines `01` as read bottom-to-top, baseline right. [3.0 Text Direction](3.0-text-direction-and-font-attributes.md#text-direction---a-third-value-and-a-redefined-second) |
| `\|f` | Attribute bits `0x01`-`0x08` given rendering behavior | **Redefinition** | ⚠ Depends on a contested opcode - `\|f` is [RIP_SET_WORLD_FRAME](../../3.0/ripscrip/1.3-world-view-virtual-canvas.md) in the 3.x record, in 90 of 116 corpus prologues ([3.0-riplib](../../3.0-riplib/ripscrip/9.0-command-inventory-comparison.md#prologue-critical---j-and-f)). Bit values also differ from the documented `\|y` style flags. [3.0 Font Attributes](3.0-text-direction-and-font-attributes.md#font-attributes-given-rendering-behavior) |

Purely rendering-side §A2G items add no wire syntax: the complete fill-pattern set (§A2G.4), FPU curves, trigonometry and pie fill (§A2G.5), and the palette index relocation (§A2G.6) are covered in [techspecs](../techspecs/README.md).

## Text variables

RIPlib tags seven variables as v3.1 additions. `spec (07 §7.6, §7.9)` Against the record here, one is new, one is arguably new, and five collide with variables that already exist - three of them with entirely unrelated, corpus-attested meanings.

| Variable | RIPlib v3.1 | Status here | Class |
| --- | --- | --- | --- |
| `$ABORT$` | Resets the parser FSM to idle, discarding any partial command | Not present in the 1.54, 2.00a4 or 3.x inventories | **Addition** |
| `$COMPAT$` | Returns `"1"` - a fixed "basic compatibility level" | ⚠ `$COMPAT(env)$` sets an environment to RIPscrip 1.54 settings - the standard 3.x legacy-mode drop, **21 corpus uses** ([3.0](../../3.0/ripscrip/9.1-text-variable-reference.md), [2.0 entry](../../2.0/ripscrip/5.1-text-variables.md#compat)) | **Redefinition** |
| `$COPY$` | Sets write mode to COPY | ⚠ `$COPY(type,source,dest,…)$` copies data tables, entries, save slots and stack ([2.0 entry](../../2.0/ripscrip/5.1-text-variables.md#copy)) | **Redefinition** |
| `$PROT$` | Returns a resolution mode index (`0` = EGA 640×350, `1` = VGA 640×480, …) | ⚠ `$PROT(object,element,…)$` protects table entries and save slots, redesigned in 2.A4 ([3.0](../../3.0/ripscrip/9.1-text-variable-reference.md)) | **Redefinition** |
| `$COFF$` | No-op - "no visible text cursor in graphics mode" | `$COFF(win,…)$` disables the text cursor in the named windows; `$COFF$$DTW$` is the standard demo prologue | **Already documented** _(reduced to a no-op)_ |
| `$MKILL$` | Clears all mouse regions | `$MKILL(x0,y0,x1,y1,inout)$` since 1.54 - kills all mouse fields, or those inside/outside a box | **Already documented** _(unparameterized form)_ |
| `$YEAR$` | 4-digit year, `YYYY` | ⚠ `$YEAR$` is the **2-digit** year; `$FYEAR$` is the 4-digit one | **Redefinition** |

The pattern is consistent across all four collisions: RIPlib's variable takes a name that in RIPscrip 2.x/3.x denotes a _parameterized action_ and re-uses it as a _bare value or unrelated action_. A host that sends `$COMPAT(0)$` to drop a `RIPSCRIP031001` terminal into legacy mode instead gets the literal string `1` rendered - a silent, visible failure rather than a caught error. These are worth raising upstream; they are not cheap to work around at the host.

For the full canonical inventories see the [3.0 text variable reference](../../3.0/ripscrip/9.1-text-variable-reference.md) (roughly 120 variables) and the [1.54 reference](../../1.54/ripscrip/9.1-text-variable-reference.md).

## Not in RIPlib's v3.1 list, but worth noting

One parser-level item carries a v3.1 label in RIPlib's other segments and is documented in [techspecs 1.0](../techspecs/1.0-stream-parsing-delta.md): the relaxed `!` command-trigger rule after ANSI CSI terminators, which the specification's SOH/STX alternate introducers already solve portably. The text-escape differences that carry v3.1-era annotations are baseline rather than extension, and live in [3.0-riplib](../../3.0-riplib/techspecs/1.0-stream-parsing-and-escapes.md).
