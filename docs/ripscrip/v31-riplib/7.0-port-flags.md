# 7.0 Port Flags - `|2F` (new command)

[◀ Prev: 3.0 Text Direction & Font Attributes](3.0-text-direction-and-font-attributes.md) · [Contents](README.md) · [Next: 9.0 Additions Reference ▶](9.0-additions-reference.md)

_A command with no counterpart in the TeleGrafix record. Delta against [7.0 Drawing Ports](../../3.0/ripscrip/7.0-drawing-ports.md) in the 3.0 reference; see the [tree README](../README.md) for standing and provenance._

The one genuinely new **command** in v3.1 - the rest of §A2G.1-7 extends existing commands or changes rendering. `|2F` attaches three compositor attributes to a drawing port, turning the port table into a layered window system. `spec (05 §5.6)`

## RIP_PORT_FLAGS

_Set extended port attributes - opacity, compositing mode, z-order_

|               |                                             |
| ------------- | ------------------------------------------- |
| **Level**     | 2                                           |
| **Command**   | `F`                                         |
| **Arguments** | `port:1 [alpha:1] [comp_mode:2] [zorder:2]` |

**Format:** `!|2F<port>[<alpha>][<comp>][<z>]`

| Parameter | Width | Range | Description |
| --- | --- | --- | --- |
| `port` | 1 | 0-35 | Target port |
| `alpha` | 1 | 0-35 | Opacity - `0` fully transparent, `35` fully opaque |
| `comp_mode` | 2 | 0-3 | Compositing mode (`0` = COPY) |
| `zorder` | 2 | 0-255 | Layer order for the compositor |

The three arguments are optional and positional. `alpha` reuses the 1-digit MegaNum range in full - `0`-`9` then `A`-`Z` - so `35` (`Z`) is opaque and is the per-port default. `spec (05 §5.6)`

Port state gains the three fields alongside the existing viewport, cursor, color, line, fill and font state defined for [RIP_DEFINE_PORT](../../3.0/ripscrip/7.0-drawing-ports.md#rip_define_port): `alpha` defaults to 35, `comp_mode` and `zorder` to 0. `spec (05 §5.1)` The existing port `flags` field (bit 0 `PORT_PROTECTED`, bit 1 `PORT_FULLSCREEN`) is untouched - despite the command name, `|2F` sets the three new attributes, not those flags.

RIPlib states the intent plainly: _"These attributes are RIPlib additions not present in any DLL version. They enable windowed desktop compositing where ports represent overlapping windows with transparency and z-ordering."_ `spec (05 §5.6)`

## Relationship to the TeleGrafix record

**No collision.** Level 2 in the reconstructed 3.x record uses command letters `T`, `A`, `B`, `R`, `P`, `s`, `p`, `C`, `W`, `Y` and `E` ([9.0 command reference](../../3.0/ripscrip/9.0-command-reference.md)); `F` is unassigned, so `|2F` is a clean addition and a 3.0 terminal will discard it as an unknown command.

**No counterpart.** Ports in 2.x/3.x are opaque scratch surfaces: content is composed offscreen and moved to the screen with [RIP_PORT_COPY](../../3.0/ripscrip/7.0-drawing-ports.md#rip_port_copy) (the most-used command in shipped 3.x content, 9,104 corpus uses), optionally scaled and with a per-copy write mode. There is no persistent per-port opacity, no z-ordered compositor, and no notion of ports being simultaneously visible and blended. Transparency in the shipped corpus is achieved through the icon/mask mechanism and through dithered fade bands, not through port alpha.

That makes `|2F` an architectural extension rather than a gap-filling one: it changes what a port _is_. Content written for it does not degrade to something meaningful on a 3.0 terminal - the ports simply behave as they always did, fully opaque and composed only when explicitly copied.

**Alpha is indexed-color, not true alpha.** RIPlib's own framing is that v3.0-era indexed color gets an _"indexed-color alpha approximation"_; the port framebuffer is `uint8_t` throughout. Blending happens against the palette rather than in a true RGBA surface, so results depend on palette contents.
