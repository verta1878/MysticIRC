# 6.0 Writing 3.x .RIP Files

[◀ Prev: 5.5 File Transfer & Queries](5.5-file-transfer-and-queries.md) · [Contents](README.md) · [Next: 6.1 Content File Roles ▶](6.1-content-file-roles.md)

_Reconstructed edition - every claim carries an evidence tag; see [Contents](README.md) for the legend._

Authoring-level conventions for 3.x script files: encoding and line endings, line length and continuation, comments and grouping, the script-container family, and the prologue/epilogue conventions of TeleGrafix's own 116 shipped RIPtel demo scripts.

_The 2.0 authoring conventions this page extends are in [6.0 of the v2.0 reference](../../2.0/ripscrip/6.0-writing-rip-files.md); the 3.0 engine inherits the 2.0 parser conventions documented in the [stream conventions techspec](../../2.0/techspecs/1.0-stream-conventions-delta.md)._

## What a .RIP file is

_Evidence: 2.00a4; corpus._

A `.RIP` file is not a distinct binary format: it is a captured RIPscrip command stream - exactly the bytes a host would transmit - stored as a text file. Everything in [1.1 Protocol & Command Hierarchy](1.1-protocol-and-command-hierarchy.md) applies verbatim to file content. A file can be transmitted by a host, replayed locally via the `$>file$` playback prefix ([5.3 Local File Playback](5.3-local-playback.md)), played back by [RIP_READ_SCENE](5.5-file-transfer-and-queries.md#rip_read_scene), or delivered and auto-played through [block mode](5.5-file-transfer-and-queries.md#rip_enter_block_mode).

## The script-container family

_Evidence: corpus (116-file census - [script census](../../3.0/research/riptel-script-census.md))._

All script extensions in the RIPtel corpus - `.RIP`, `.FN`, `.DEF`, `.MNU`, `.MSE`, `.RET`, `.ENT`, `.EXT`, `.COL` - are plain-ASCII RIPscrip command streams distinguished only by **role**, not by format. The corpus-attested roles:

| Extension | Role |
| --- | --- |
| `.RIP` | A scene - the general-purpose script container |
| `.FN` | A "function" scene invoked as a subroutine via [RIP_READ_SCENE](5.5-file-transfer-and-queries.md#rip_read_scene) or the `$>file$` playback prefix - the WIPE00-24 transition library, effects, and reusable setup blocks |
| `.DEF` | A variable-definition script (TELCMDS.DEF, MENU.DEF …) that seeds [text variables](../../glossary.md) for a scene group |
| `.MNU` | A menu scene (buttons, mouse fields, navigation) |
| `.MSE` | A mouse-field overlay scene wiring field entry/exit queries to status-line updates and cursor changes |
| `.ENT` / `.EXT` | Menu entry/exit transition stubs that save and restore the screen around a menu excursion ("Paste original screen image back" - see [7.2 Data Backup Areas](7.2-data-backup-areas.md)) |
| `.RET` | Return scenes replayed when control comes back from a linked demo (MENU.RET, TELCMDS.RET - invoked through RIP_READ_SCENE) |
| `.COL` | A "column layout" scene built on the flowed-text column system, paired with raw-prose `.TXT` story files - see [3.1 Column Text System](3.1-column-text-system.md) |

`.TXT` story files flowed into column regions are the one non-RIPscrip participant: inside an open column region they are word-wrapped as raw content, never parsed as commands ([3.1](3.1-column-text-system.md)). Playback search paths for all of these are covered in [5.3](5.3-local-playback.md) and [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md).

## Encoding and line endings

_Evidence: 2.00a4; corpus; SyncTERM (ripper.c:18557-18580)._

- **Line endings are CRLF** throughout the RIPtel corpus (the 1.54 spec said bare CR). They parse identically because CR dispatches the pending command while LF is unconditionally swallowed mid-command - see [1.1](1.1-protocol-and-command-hierarchy.md). Line endings are significant to the parser, so script files should be stored and transferred byte-exact - never re-wrapped or "normalized". Script files also contain **literal control bytes** - SOH (`0x01`) introducers and ESC (`0x1B`) command characters - so they are not safely editable in tools that strip or transcode control characters.
- Text content (graphics text, button labels, embedded raw text) is [CP437](../../glossary.md) - the code page of the BBS world, and the character set the 3.x client's MicroANSI terminal fonts render in full (all 256 glyphs; see [6.1](6.1-content-file-roles.md)). There is no in-band encoding declaration. _Evidence: 2.00a4; corpus (FONTS/RIPscrip.maf glyph complement)._

## Line length and continuation

_Evidence: 2.00a4 rules 4-5, 13; corpus._

Any command or line may be split with a backslash (`\`) immediately before the line break; continuation lines carry **no introducer** - they are bare argument bytes. Authoring practice:

- The split may land anywhere - mid-parameter, mid-number. The RIPtel corpus uses continuation for long vertex lists (POLYPOLY.RIP's RIP*FILL_POLYGON runs); the RIPterm 2.30 shipped corpus shows it as heavy production traffic (one palette-fade file is 1,024 physical lines of which 960 are continuations). \_Evidence: corpus (POLYPOLY.RIP); 2.00a4.*
- The 2.0-era 80-column discipline for command lines remains sound authoring advice - wrap for tool compatibility, but don't rely on readers enforcing any limit; terminals accept arbitrarily long lines. _(Inherited RIPterm 2.30-corpus observation - see the [v2.0 page](../../2.0/ripscrip/6.0-writing-rip-files.md).)_
- Watch trailing backslashes: an **odd** count means continuation, an **even** count means escaped literal backslashes. If you need a literal `\` at end-of-line, write `\\`; a continuation after a literal backslash needs `\\\`. _Evidence: 2.00a4 rule 13; SyncTERM (ripper.c:18563-18576)._
- Multi-command lines are the norm - `|` chains commands on one line (`!|c0F|=00000001|S010F`), and the standard 3.x prologue is itself a four-command chain (below). Commands that must be last on their line (RIP*READ_SCENE, RIP_ENTER_BLOCK_MODE) cannot be chained past. \_Evidence: 2.00a4 rule 4; corpus.*

## Escaping, comments and grouping

_Evidence: 2.00a4 rules 11, 14; corpus._

Inside text parameters, `\!` → literal `!`, `\|` → literal `|`, `\\` → literal `\`; [host command](../../glossary.md) and text-variable metacharacters (`$`, `[`, `]`, `(`, `)`) are quoted with a backslash where they could be misread (`\$Name\$`) - see [1.1](1.1-protocol-and-command-hierarchy.md). At the file level:

- **Comments** - `!|!comment text` embeds a comment anywhere ([RIP_COMMENT](1.1-protocol-and-command-hierarchy.md#rip_comment), _(v2.A2)_); everything from the `!` opcode to the next `|` or end of line is ignored, and the comment string is exempt from text-variable substitution. The RIPtel corpus contains **1,683 comment commands** (305 with prose): `!|command|! comment` chains are ubiquitous, and TeleGrafix's authors left positional field-layout cribs above complex commands (`!|! xxyyxxyycaffffccrrrrrrrr`). _Evidence: 2.00a4; corpus._
- **Trailing text after fixed-length arguments is tolerated** and used as inline commentary - the shipping driver stops reading once a command's fixed fields are consumed: `!|fZKQO                 Set world coordinats to 1280x960` _(sic)_. Robust for the shipping driver, but not guaranteed by the language - prefer explicit `|!` comments. _Evidence: corpus (ONLINE.RIP)._
- **Grouping** - `!|(` … `!|)` bundles commands into logical groups for paint programs ([RIP_GROUP_BEGIN](1.1-protocol-and-command-hierarchy.md#rip_group_begin)/[RIP_GROUP_END](1.1-protocol-and-command-hierarchy.md#rip_group_end), _(v2.A2)_); terminals ignore them, and the 2.00a4 advice to strip groups from files placed online is consistent with their total absence from the shipping demo corpus. _Evidence: 2.00a4 - not in the RIPSCRIP.HLP inventory, not observed in the RIPtel demo corpus._
- **UU-encoded data blocks** - a file (or stream) may embed raw binary content behind a [RIP_BEGIN_UUENCODE_BLOCK](5.5-file-transfer-and-queries.md#rip_begin_uuencode_block) command _(v2.A1)_; the 3.0 driver renamed the mechanism `RIP_BeginEncodedStream`. _Evidence: 2.00a4; HLP - not observed in the RIPtel demo corpus._

## Mixing ANSI, raw text and column content

_Evidence: 2.00a4 rule 6; corpus._

Lines that do not begin with an introducer pass through to the current [text window](../../glossary.md) ([1.4 Terminal & ANSI View](1.4-terminal-ansi-view.md)), so script files freely intermix RIPscrip with ANSI sequences and plain text. The flowed-text machinery extends the 2.0 modal wrinkle: after a text-region or column-region definition ([3.0](3.0-text-output-and-fonts.md), [3.1](3.1-column-text-system.md)), raw lines are consumed as region/column content until a command line ends the block - the `.COL` scenes and their `.TXT` story files are built entirely on this.

## The SOH scene-start opener

_Evidence: 2.00a4 rule 12; corpus._

Ctrl-A (SOH, byte `0x01`) or Ctrl-B (STX, `0x02`) may replace the `!` introducer and - unlike `!` - are accepted anywhere in the stream, not just at line start ([1.1](1.1-protocol-and-command-hierarchy.md)). TeleGrafix's 2.2-era convention was to open a standalone scene file with `\x01|*` (SOH + [RIP_RESET_WINDOWS](1.3-world-view-virtual-canvas.md#rip_reset_windows)); the 3.x corpus systematizes the SOH opener: **111 of 116 files begin their _first_ command line with SOH + `|`**, then use `!|` for every subsequent line - SOH apparently flags start-of-scene to the 3.0 stream parser, while `!|` remains the 1.54-compatible introducer. (Three files invert the pattern, nearly all-SOH; SOH mid-scene is legal and does appear, e.g. in DRAGON.RIP below.) Files that are deliberately non-destructive (wipes, fades, fragments) omit the `*` reset.

## Scene prologue and epilogue conventions

_Evidence: corpus (90+ files); HLP._

TeleGrafix never specified how a script file should begin or end, but their shipped 3.x scenes are consistent:

- **The standard prologue** opens 90+ of the 116 files: `!|J10|n2000|M08|fZKQO` - pinning the scene's numeric conventions _before_ any coordinate-bearing command arrives (order matters). Decoded:

| Piece | Command | Meaning |
| --- | --- | --- |
| `!\|` | - | line introducer + command delimiter |
| `J10` | [RIP_SET_BASE_MATH](1.2-math-and-coordinates.md#rip_set_base_math) | [Base Math](../../glossary.md) ← 36 (`10` base-36 = 36): [MegaNums](../../glossary.md). The shipped opcode is level-0 `J`; the ALPHA 4 draft's `b` assignment collided with RIP_EXTENDED_TEXT_WINDOW - see the [1.2 note](1.2-math-and-coordinates.md#rip_set_base_math) |
| `\|n2000` | [RIP_SET_COORDINATE_SIZE](1.2-math-and-coordinates.md#rip_set_coordinate_size) | coordinates ← 2-digit fields |
| `\|M08` | [RIP_SET_COLOR_MODE](2.0-color-modes-and-palettes.md#rip_set_color_mode) | 8-bit palette color mode |
| `\|fZKQO` | [RIP_SET_WORLD_FRAME](1.3-world-view-virtual-canvas.md#rip_set_world_frame) | world frame ← 1280×960 (`ZK`=1280, `QO`=960) |

- **Reset first** - standalone scenes open with the SOH reset opener (`\x01|*` or `!|*`), then the prologue; [RIP_KILL_MOUSE_FIELDS](4.2-mouse-fields-and-pointer.md#rip_kill_mouse_fields) (`!|1K`) clears stale fields so they cannot fire during the redraw (8 corpus files; TELKILL.FN wraps it as a reusable subroutine scene). _Evidence: corpus._
- **Query-command setup** - the demos do much of their scene setup through [RIP_QUERY](5.5-file-transfer-and-queries.md#rip_query) terminal-control variables alongside the prologue: `$COFF$` (cursor off), `$DTW$` (deactivate text window), `$SBAROFF$` (hide status bar), `$RESET(OVERFLOW)$` (clear column-overflow state). _Evidence: corpus._
- **Scene header segments** - the 3.0 engine formalizes the 2.A1 [RIP_HEADER](1.1-protocol-and-command-hierarchy.md#rip_header) idea into structured header segments declaring the environment a scene expects (per-table flags, coordinate size, RGB bit count, revision code - see [1.1](1.1-protocol-and-command-hierarchy.md) and [7.1](7.1-data-tables.md#scene-header-segments-and-table-state)). No wire-format example has been recovered - the RIPtel demos use the explicit prologue commands instead - so the segment encoding remains undocumented _(hypothesis: a parameterized RIP_HEADER-style command, per the 2.A1 design)_. _Evidence: HLP._
- **State re-assertion** - authored streams re-assert unchanged state constantly (background color, write mode, fonts); state is inherited from whatever ran before, so well-behaved scenes re-establish everything they depend on. _Evidence: 2.00a4; corpus._
- **Epilogue** - [RIP_NO_MORE](1.1-protocol-and-command-hierarchy.md#rip_no_more) (`!|#`) marks scene end, activating mouse regions and queued clicks; nearly every RIPtel demo scene ends with one (287 uses in 95 of 116 files). The spec's advice to transmit three or more consecutively for noise immunity stands - the shipped RIPterm 2.30 scenes ended `!|#|#|#` - and terminals should also time out and assume NO*MORE if the stream goes quiet. \_Evidence: 2.00a4; corpus.*

### A real scene opening (DRAGON.RIP)

_Evidence: corpus (DRAGON.RIP; annotations editorial)._

```text
\x01|!                                    SOH scene-start + comment (no text)
!|*                                       RIP_RESET_WINDOWS - clean slate
!|1\x1b0000$-=NO_WIPES=Disabled$          query cmd sets variable NO_WIPES=Disabled
!|1\x1b0000$SBAROFF$                      hide the status bar
!|w0000000000                             RIP_TEXT_WINDOW - zero-size (off)
\x01|1\x1b0000$DTW$                       disable text window
\x01|1\x1b0000$COFF$                      cursor off
\x01|1\x1b0000$RESET(OVERFLOW)$           clear column-overflow state
\x01|n2000                                2-digit coordinates
\x01|M08                                  8-bit palette mode
\x01|W00                                  RIP_WRITE_MODE - COPY
\x01|fZKQO                                world frame 1280x960
\x01|2P10000ZKQO00030000                  RIP_DEFINE_PORT - offscreen port 1, 1280x960
\x01|J10                                  base math 36 (MegaNums)
\x01|1b0000HS0Y000G000000STRIP6.BMP       RIP_LOAD_BITMAP at (0,0), 640x34 region
\x01|c0F                                  draw color 15
\x01|y0000BW0X040000001a1a000000dixon     extended font style - outline font "dixon"
```

(`\x01` = SOH, `\x1b` = ESC; both are literal single bytes on the wire. Lines end CRLF. Note the mixed introducers - SOH mid-scene is legal - and `$…$` terminal-control variables doing setup work alongside drawing commands.)

## Authoring-robustness notes from the corpus

_Evidence: corpus._

The shipping driver's parser is markedly tolerant, and shipped TeleGrafix files lean on that tolerance - a caution for authors targeting other terminals:

- **Typo tolerance is high.** A missing `!` introducer (`|1<ESC>0000$COMPAT$`, CURVES.RIP), separator lines `!|----` that accidentally parse as the `-` opcode with dash arguments (`-` reads as MegaNum 0), and bare `!|` no-op lines all pass through the shipping driver without visible failure. Robust parsers should degrade as gracefully; robust authors should not rely on it.
- **Truncated reserved fields are routinely omitted** (`!|2s002` for a documented 6-character argument block; `!|1c06` with no reserved digits). The documented practice remains to send reserved fields as zeros for forward compatibility.

## Naming and delivery

_Evidence: 2.00a4; HLP._

Files referenced from commands and playback variables use bare DOS-style names - no path or sub-directory information (commands that take filenames reject paths). Extensions may be omitted where a command documents a default (`.RIP` for playback variables, `.BMP` for icon commands). Where files live on the terminal and how a host delivers them is covered in [6.2 Asset Delivery & Storage](6.2-asset-delivery-and-storage.md).
