# Transport / Grammar Isolation - Implementation Plan

Branch: `rescue/transport-isolation-on-main-20260618`.
Status: integration branch on current `main`; host tests pass with the default
toolchain, but size/ABI guards must pass before merge/HW release.

This is the implementation plan for making the protocol grammar reusable while
keeping transport behavior out of the application loop. It supersedes the
earlier proposal in this file.

Current branch progress:

- Common game payload grammar exists in `src/common/protocol/game_protocol.*`
  and is consumed by Spectrum/PC-facing code where this branch has touched it.
- Spectrum `app.c` now consumes common inbound game grammar for ACK, NACK, BYE,
  RESET, and GAME START instead of parsing those payloads inline. Test-only
  game formatters live in a separate compilation unit so the Spectrum build can
  link only the parser side.
- Common MQTT-session grammar exists in
  `src/common/protocol/mqtt_session_protocol.*`.
- Spectrum MQTT session state and MQTT-session event classification live in
  `src/spectrum/session/`; `app.c` handles named session actions/events instead
  of parsing `H`/`J`/`F`/offline payloads inline.
- Direct session handshake grammar lives in
  `src/common/protocol/direct_session_protocol.*`; `src/spectrum/session/direct.c`
  applies named direct-session outcomes instead of matching `HELLO DIRECT ...`
  or `GAME START WHITE=...` strings inline.
- MQTT PINGRESP is hidden from `app.c`, retained delivery is exposed through
  neutral payload flags, and MQTT ping send goes through a transport API.
- Direct textual keepalive grammar is isolated in
  `src/spectrum/transport/keepalive_protocol.*`.
- Direct/MQTT liveness counters and idle servicing live behind the Spectrum
  session/link boundary; `app.c` receives only non-keepalive session events.

No-baseline policy remains in force: size/ABI baselines are not regenerated by
this branch unless a later change explicitly justifies it. The current resident
size debt is intentional for this experimental isolation branch and is expected
to be absorbed by the parallel shrink work before HW validation.

---

## 1. Goal

Shatranj has a Spectrum client and a Qt PC client today, plus a planned
Flutter/Dart client. They must agree on the same wire payloads, but only the
transport layer should know how those payloads move.

The target boundary is:

- `src/common/protocol/`: host-portable payload grammar shared by clients.
- Spectrum transport: ESP/direct TCP/MQTT framing, MQTT PINGREQ/PINGRESP,
  retained metadata, and link liveness.
- Spectrum session state: direct/MQTT negotiation decisions, expressed as named
  actions for the app loop.
- Spectrum app/UI: game flow, board state, input, notifications, and rendering.

Wire behavior must stay byte-compatible with the current `themes` behavior. This
is a refactor, not a protocol migration.

## 2. Current Leaks

### Leak A - `src/common/protocol/` is documented but absent

`docs/source-layout.md` already names `src/common/protocol/`. Before this
branch, grammar ownership was split:

- Spectrum parsed game payloads in Spectrum-only code.
- The PC client re-parses and formats message strings inline in
  `src/pc/client/main.cpp`.
- Formatting is also ad hoc in Spectrum `app.c`.

The common grammar is broader than `MOVE`/`CHAT`: `ACK`, `NACK`, `GAME START`,
`RESET`, and `BYE` are also shared game-loop payloads. If those remain inline,
the Dart port still needs to copy behavior from application code.

### Leak B - MQTT keepalive escapes the transport

`spectrum_net_mqtt_read_payload()` maps its timeout to the neutral
`SPECTRUM_NET_READ_TIMEOUT`, but returns `SPECTRUM_NET_MQTT_PINGRESP` upward.
`app.c` then resets `mqtt_ping_misses` directly.

The old app path sent MQTT keepalive through a textual ping payload. That path
is obsolete: MQTT keepalive now goes through the transport link ping API and is
emitted as binary PINGREQ.

### Leak C - MQTT payload metadata escapes as an MQTT-only query

The app asks `spectrum_net_mqtt_payload_retained()` after every received MQTT
payload. Retained status is a property of the transport delivery, not game
grammar. The app may need to ignore retained setup/game messages, but it should
receive that as neutral payload metadata.

### Leak D - MQTT session grammar is smeared through app and PC code

MQTT setup/presence payloads (`H`, `J`, `O`, `F`) are parsed in `app.c`, and
equivalent rules exist in the Qt client. These messages are MQTT-session
protocol, not MQTT packet transport and not board/game grammar.

This coupling is partly inherent: direct TCP and MQTT really negotiate sessions
differently. The fix is not to pretend the sessions are identical. The fix is
to name the MQTT session contract and keep its parsing/state transitions out of
the main game loop.

## 3. Constraints

- Spectrum resident code is size-constrained. Run `make size-check` whenever
  Spectrum code changes.
- Overlay ABI is guarded by `make abi-check`.
- SDCC IY calling convention is guarded by `make sdcc-iy-contract-check`.
- Host tests must stay green with `make test`.
- The Qt client must keep building with `make client`.
- Shared protocol C must be host-portable: no Qt, no Spectrum headers, no heap,
  no stdio, and no SDCC-only constructs.
- Do not regenerate `docs/size_report.baseline.json` or
  `docs/abi_manifest.baseline.json` unless the size/ABI change is intentional
  and explicitly called out.

## 4. Implementation Plan

Each phase should be independently committable. Run the listed verification gate
before moving to the next phase.

### Phase 0 - Baseline the branch

Purpose: know whether failures are introduced by this work.

1. Confirm branch is `experiment/transport-isolation`.
2. Run:
   - `make test`
   - `make client`
   - `make size-check`
   - `make abi-check`
3. Record any pre-existing tool or environment failure in the commit/notes.
4. Do not update baselines in this phase.

Gate: no code changes.

### Phase 1 - Add canonical game payload grammar

Purpose: create the common grammar the Dart port can safely copy or bind to.

Create `src/common/protocol/game_protocol.{h,c}` with parser/formatter helpers
for game-loop payloads:

- `MOVE <ply> <move> [notation]`
- `CHAT <text>`
- `ACK <ply> [notation]`
- `NACK <ply> [reason]`
- `GAME START`
- `RESET`
- `BYE`

Do not put transport/session keepalive in this module:

- no MQTT PINGREQ/PINGRESP
- no textual direct `PING`
- no direct `HELLO DIRECT ...`
- no MQTT setup/presence `H`/`J`/`O`/`F`

Implementation notes:

1. Keep APIs buffer-based and tiny, e.g. explicit output buffers plus caps.
2. Preserve current parsing quirks where they are wire-visible:
   - move length 4 or 5
   - notation optional
   - numeric clock token after MOVE remains ignored as notation
3. Add `tests/net/test_game_protocol.c` before repointing callers.
4. Do not reintroduce `legacy_protocol.{h,c}`; repoint callers directly to the
   common parser side when needed.
5. Add the new common source to:
   - `Makefile`
   - `client/CMakeLists.txt`
   - `client/shatranj.pro`
6. Update `docs/source-layout.md` to match the real directory.

Gate:

```sh
make test
make client
make size-check
make abi-check
```

### Phase 2 - Repoint Spectrum and PC to the game grammar

Purpose: remove duplicated game grammar from application code.

Spectrum changes:

1. Replace `spectrum_protocol_parse_move/chat` call sites with
   `netchess_proto_*` helpers, or keep the shim for one commit if that makes the
   diff smaller.
2. Replace ad hoc `MOVE`, `CHAT`, `ACK`, `NACK`, `GAME START`, `RESET`, and
   `BYE` formatting where the common formatter is not larger.
3. Keep direct-only `PING` and `HELLO DIRECT` handling out of
   `game_protocol`.

PC changes:

1. Replace inline `MOVE` parsing in `handleRemoteMove()` with the common parser.
2. Replace inline `CHAT`, `ACK`, and `NACK` prefix handling where practical.
3. Keep Qt UI decisions in C++; only payload syntax moves to C.

Gate:

```sh
make test
make client
make size-check
make abi-check
```

Exit criteria:

- `src/common/protocol/game_protocol.*` is the single source for shared
  game-loop payload syntax.
- PC and Spectrum tests cover the same edge cases.
- No wire payload text changes.

### Phase 3 - Add canonical MQTT session payload grammar

Purpose: separate MQTT-session protocol from MQTT packet transport and from UI.

Create `src/common/protocol/mqtt_session_protocol.{h,c}` for pure parsing and
formatting of MQTT session/presence payloads:

- `H <W|B> <session_id>`
- `J <session_id>`
- `O <side> <session_id>`
- `F <side> [session_id]`

Implementation notes:

1. Keep topic suffix construction in the existing Spectrum/PC transport code
   unless moving it to common clearly reduces duplication without increasing
   Spectrum size.
2. Add host tests for valid/invalid host, join, online, offline, and stale
   session parsing.
3. Repoint the Qt client session parsing/formatting to this module first; it is
   less size-sensitive and gives quick confidence.
4. Repoint the Spectrum MQTT setup/presence parsers next.

Gate:

```sh
make test
make client
make size-check
make abi-check
```

Exit criteria:

- `mqtt_parse_host_payload` and `mqtt_parse_join_payload` no longer live as
  private app-loop grammar.
- All clients consume the same MQTT session payload parser.

### Phase 4 - Neutralize the transport read and keepalive contract

Purpose: make `app.c` stop seeing MQTT packet concepts and stop initiating MQTT
keepalive as fake text payloads.

Public `net.h` contract:

- Keep `>= 0` as "payload data available" to minimize churn.
- Keep/rename neutral negative results only:
  - peer gone: current `-2`, named as a neutral constant
  - timeout/no data: `SPECTRUM_NET_READ_TIMEOUT`
- Remove `SPECTRUM_NET_MQTT_PINGRESP` from public app use.
- Hide `SPECTRUM_NET_MQTT_READ_TIMEOUT` inside the MQTT implementation.
- Add neutral payload flags, e.g. `SPECTRUM_NET_PAYLOAD_RETAINED`, available via
  a transport-neutral query such as `spectrum_net_payload_flags()`.

Keepalive contract:

1. Keep idle counters and ping-miss policy behind `src/spectrum/session/poll.c`;
   `app.c` should see only poll outcomes.
2. Keep the actual ping send operation behind the transport-neutral link API.
3. MQTT sends binary PINGREQ directly from transport/overlay code and consumes
   PINGRESP internally.
4. Direct TCP keepalive uses exact `PING` / `ACK PING`, but the app loop should
   no longer dispatch those payloads as game messages.
5. Incoming keepalive packets should be consumed before app dispatch and
   surfaced as no game payload.

Gate:

```sh
make test
make size-check
make abi-check
make sdcc-iy-contract-check
```

Manual gate:

- idle direct TCP link stays alive
- idle MQTT link stays alive
- unplug/drop link path still reaches opponent-disconnected UI

Exit criteria:

- No `SPECTRUM_NET_MQTT_*` symbol is referenced from `app.c`.
- `mqtt_ping_misses`, `direct_ping_misses`, and direct ping sequence state are
  not owned by the app loop.
- `app.c` no longer calls `spectrum_net_mqtt_payload_retained()`.

### Phase 5 - Extract Spectrum MQTT session state

Purpose: stop spreading MQTT-session decisions through the main game loop.

Create a named Spectrum session unit under `src/spectrum/session/` because it
owns Spectrum session state, not byte transport. It should use
`common/protocol/mqtt_session_protocol.*` for syntax.

The unit should own:

- remote peer ready state
- MQTT session id acceptance rules
- host-color application rules
- retained setup/presence behavior
- peer-offline matching
- room-conflict detection

Expose actions back to `app.c`, for example:

- ignore payload
- peer ready
- peer offline
- room conflict
- host color accepted
- activate side required
- game payload, continue to game protocol parser

Implementation notes:

1. Move parser-free state transitions first; leave UI calls in `app.c`.
2. Return actions and let `app.c` decide notifications, board redraw, and waits.
3. Keep direct session handling local until MQTT is clean. Do not build a large
   generic direct/MQTT polymorphic layer unless it reduces code size or removes
   obvious duplication.

Gate:

```sh
make test
make size-check
make abi-check
make sdcc-iy-contract-check
```

Exit criteria:

- The main game loop dispatches MQTT session outcomes by named action, not by
  parsing `H`/`J`/`O`/`F` inline.
- `netchesszx_transport_is_mqtt()` remains in `app.c` only for setup,
  connection startup, and genuinely different UX/status text.

### Phase 6 - Documentation and final cleanup

Purpose: make the new boundary obvious to the next port/client.

1. Update `docs/source-layout.md`.
2. Document the final payload grammar in a short protocol note, or add comments
   in the common headers if that is enough.
3. Keep obsolete `legacy_protocol` files out of the Spectrum build.
4. Search for forbidden leaks:
   - `SPECTRUM_NET_MQTT_` in `app.c`
   - private MQTT parser functions in `app.c`
   - inline MOVE parsing in `main.cpp`
   - `spectrum_net_mqtt_payload_retained()` outside transport/session code

Final gate:

```sh
make test
make client
make size-check
make abi-check
make sdcc-iy-contract-check
```

Manual compatibility gate:

- Spectrum direct host vs PC direct guest
- Spectrum direct guest vs PC direct host
- Spectrum MQTT host vs PC MQTT guest
- Spectrum MQTT guest vs PC MQTT host
- MOVE, CHAT, ACK, NACK, RESET, BYE, reconnect/offline paths

---

## 6. Stop / Defer Criteria

It is acceptable to stop after Phase 2 if the immediate goal is only to unblock
the Dart game grammar. Phases 3-5 are still the right direction, but they touch
live session and keepalive behavior and require manual transport testing.

Defer a cleanup if:

- it increases resident size without removing a real leak
- it forces a baseline update for a non-functional rename
- it turns direct TCP and MQTT into a large generic abstraction with no code-size
  or clarity win

Do not defer:

- moving shared game payload syntax to `src/common/protocol/`
- hiding MQTT PINGRESP from `app.c`
- keeping MQTT ping on the transport keepalive API
- making retained payload status transport-neutral
